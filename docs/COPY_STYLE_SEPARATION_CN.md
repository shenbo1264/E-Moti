# E-Moti 文案双轨规范

## 1. 游戏内角色文案

目标：让星汐听起来像有性格的桌面小宠，而不是系统通知或客服机器人。

允许：

- 轻口癖：唔、欸、哼哼、……；
- 少量卖萌、害羞、轻吐槽；
- 短句、动作感、桌角与星光意象；
- 主动靠近，但被拒绝后立即收住。

禁止：

- “检测到、建议、当前状态、正在处理”等系统通知语气；
- 大段解释、总结式结论；
- 情感绑架、内疚诱导、依赖暗示；
- 每句话都堆口癖、颜文字或网络梗。

## 2. 公众号文章

目标：像作者本人写的项目报告与产品复盘。参考此前《英雄联盟》作业的表达方式：先给作品和问题，再展开机制、设计意图、风险与边界；允许少量个人经历和括号补充，但不模仿 ACG 社区口癖。

禁止：

- “啊喂、冲鸭、绑定地狱、通知栏成精”等社区化表达；
- “不仅……更……、真正的价值在于、这意味着、赋能、闭环”等模板化 AI 句式；
- 将尚未合入正式客户端的原型写成已经上线；
- 用二次元角色口吻替代作者正常说明。

两条轨道不能混用：角色可以卖萌，作者必须说人话。
