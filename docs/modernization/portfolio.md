# AI 产品经理展示：可验证的技术成果

这份材料用于介绍实际完成的产品与技术工作。应以本轮代码、验证结果和决策证据为依据；不把下一阶段路线图当已交付功能，不编造用户增长、留存、满意度或线上准确率。

## 项目定位

**E-Moti：具有稳定人格、共同记忆和可控主动性的个人 AI 伙伴。** 工作、游戏、现实感知是可选能力；关闭这些能力仍保有独立陪伴体验。本轮重点从“记忆模块存在”推进到“记忆能在真实交互入口生效，并尊重纠正和遗忘”。

## 一段可以放进项目介绍的表述

> 负责 E-Moti 开源 AI 桌宠的 Personal Companion 升级，完成记忆框架、具身伙伴及商业陪伴产品调研和源码审计，形成稳定人格、用户事实、共同经历、外部短时状态的产品边界。沿用 Python/PySide6 和原有角色存档，实现来源可追溯的记忆修订、派生失效、跨角色/owner/场景隔离与用户确认界面，并打通实际 LLM prompt。建立同一 runner 的新旧版本对照及 38 条确定性生命周期用例；代码、失败案例、迁移说明和验证记录均可复现。

38 条是开发契约集，涵盖中文合成轨迹，没有冒充真实用户总体质量。最终全量测试数量以 [verification.md](verification.md) 为准。配置 hash 稳定只能证明人格配置未被改写；真实模型人格稳定、陪伴满意度和留存尚未测量。

## 面试讲述结构

### 情境与问题

已有项目具备 Emotional Memory V2、CoreBondProfile、角色隔离与插件体系，表面上功能齐备。审计真实数据流后发现 V2 上下文在 typed request 白名单处丢失；忘记操作只改活动条目，旧章节、画像、聊天和迁移仍可能重新提供旧事实。用户体验问题因此同时包含“记不住”和“忘不掉”。

### 产品判断

将“共同生活连续性”拆成可检验的契约：有证据的共同经历、稳定角色身份、用户可管理事实、外部状态不污染人格、主动陪伴不等于任务监督。用原型和基准明确哪些只是模块 API、哪些真正进入了最终模型请求。

### 技术取舍

没有将桌宠重写为另一个 Agent 平台。保留现有数据对象与 PySide6 运行时，把原先三份分开提交的 JSON 改为单一 SQLite 事务文档；Graphiti 只复用适合本项目的 RRF 小组件并保留 Apache-2.0。将来源指纹、退役来源与 epoch 作为失效传播的基础，先解决正确性，再评估 embedding 的收益。

### 实施与结果

用户可以提议/确认/查看来源/纠正/遗忘，旧事实和其已知派生物不再通过本批覆盖的入口进入后续 prompt。38 例新旧对照同时衡量事实交付和撤回，避免用“完全没有接入记忆”的低泄露假象证明系统优秀。语义检索、人格式样和真实模型效果的证据等级在结果中明确分开。

本轮还发现了“到期事实已经从 recall 中过滤，但旧聊天仍含该事实”的遗漏，将其加入数据集并修复。面试时可以展示这一例：它能说明端到端评测为什么比模块有无更重要，也说明迭代中的失败如何改进产品验收标准。

可引用的实际工程结果是：相同38例从 **12/38** 到 **38/38**；正向最终 prompt 交付从 **0/11** 到 **11/11**；全量 **1333通过、1项既有平台失败**，相比基线新增149项测试。必须同时说明这不是实测用户留存、总体记忆准确率或模型人格盲评分数。

## 建议展示的四张证据页

1. 产品定位与状态职责：为什么工作系统不是 E-Moti 的人格真源，关闭插件后用户仍能使用。
2. 实际数据流与断点：旧版 context→typed request 的 V2 丢失，新版来源/版本→最终 prompt 的闭环。
3. 对照表与 bad case：同时呈现 baseline 和 after、全部分母、未验证指标，不只展示“全通过”。
4. 回忆册实际截图与迁移契约：用户确认和纠正入口、存档保留、旧备份/物理删除边界。

## 不应写入简历的说法

- “长期记忆准确率100%”“零幻觉”“绝对无泄露”：38条确定性开发用例不支持这些结论。
- “已实现全自动人格成长/真实世界自主陪伴”：当前是只读人格输入与受控记忆，后续仍有模型与体验实验。
- “提升留存/满意度X%”：没有线上产品实验或用户研究数据。
- “毫秒级模型响应”：本批只测本地上下文与 prompt 构造；网络、模型和语音不在该计时内。
- “完全独创记忆算法”：本批明确复用了 Graphiti RRF，核心价值在正确的系统契约、集成、验证与产品控制。

下一步可以补一轮小规模、知情同意的体验研究：只聊不工作、休闲游戏、安静陪伴三种场景，观察主动消息接受/忽略/关闭、纠正成功率、来源理解和风格稳定，并保留访谈与问题轨迹。此处是研究计划，不是已获取的用户反馈。
