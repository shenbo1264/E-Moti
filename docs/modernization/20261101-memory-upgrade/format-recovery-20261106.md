# 表达格式失败与一次审阅修复

本批在 `2db8739` 后端基础上修复生产表达链，保留原来的角色、台词提示、事件解析和一次审阅预算。没有改变模型协议、全局推理配置或真实存档。

## 原因与实现

第六份独立集的生成工具直接执行 `client(prompt)`，没有经过桌面 `ShinsekaiAIExpressor.express()` 的台词审阅。因此，原来的两条生成格式失败与桌面最终交付失败不能等同计数。旧数据不修改。

- 一条输出把 `speech` 键写成表情标签。它是合法 JSON，但不是合法表达事件。旧生产代码直接返回错误草稿，没有进入已有审阅。
- 另一条输出的冒号结构不合法。旧生产代码已经会把该原文作为引用草稿交给一次审阅，本次不把它算作新增修复。

现在，`type=speech` 的对象未通过事件校验时，也以完整原文作为只读草稿交给已有审阅。未验证的对象字段不会复制到最终事件；审阅只允许返回 `edits` 与 `speech`，最终台词继续执行原来的长度、格式与事件校验。非表达对象和数组仍保持原处理。没有按测试人物、活动或回答内容写转换规则，也没有在本地猜测哪段文本应成为台词。

审阅仍最多一次，与草稿使用同一不可变请求、future 和截止时间。本批另修复审阅调用返回后的取消检查：用户在审阅期间取消，迟到结果不再产生可呈现的事件或动作。审阅自身格式失败仍明确返回 `invalid_refinement`，不会进行第三次调用或放宽解析。

## 实际验证

原始记录：`artifacts/codex_handoff/memory-upgrade/format-recovery-20261106/before-after.json`。

| 场景 | 修改前 | 修改后 |
|---|---|---|
| 原始坏键响应回放，随后需要时真实审阅 | `unsafe_event`，未审阅 | 一次真实审阅，正确交付排版事实 |
| 原始非法 JSON 响应回放，随后真实审阅 | 成功 | 成功；属于原有能力 |
| 重新生成两个事实问题 | 2/2 原始格式合法、最终可交付 | 2/2 原始格式合法、最终可交付 |
| 无答案问题 | 简短不知道 | 简短不知道 |
| 角色玩笑 | 保留星星绰号的拟人玩笑 | 保留星星绰号的拟人玩笑 |

总计 **19 次真实 HTTP 请求、47,576 provider tokens、39.25 秒请求耗时合计**，模型请求和返回名称均为 `deepseek-flash`。两个历史草稿分别回放到新旧链路，共四次历史响应复用不计入实际请求。每条记录分别保存草稿原文及格式状态、最终事件、失败原因、真实请求、完整响应、usage 和耗时。历史回放不是重新生成失败的证据，四个重新生成场景的新旧草稿本次都未出现格式错误。

本批对最终文本的核对为开发者复核，尚不是独立人格盲评。事实回答准确、无答案短答没有追问、星星绰号回答保留角色玩笑；不能据此宣称任意模型输出均可修复或人格质量已经全面提高。这些题已参与开发，只能作为回归，新泛化结论由后续密封样本单独给出。

调用边界先复现旧版失败，再修复。相关 **163 项测试通过**，包括原始格式回放、禁止复制未验证字段、取消、截止时间、审阅失败不增加第三次调用，以及既有客户端与解析测试。后补的取消检查不改变模型提示或正常回应，真实对照发生在该检查补充前，其对应的最终取消行为由独立失败与通过记录验证。全量回归由本轮集成主任务统一执行。

## Provider 能力核查

实际查阅 [DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)。当前 Chat 的 `response_format` 支持 `json_object`，不提供本次表达 schema 的直接约束；严格函数参数模式要求 beta 接口与工具调用协议。本批复用现有生产审阅链，没有为这两个已知缺口切换整套表达传输。即使返回 JSON，字段是否符合表达事件仍必须由本地校验。
