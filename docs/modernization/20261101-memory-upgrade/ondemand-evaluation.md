“有证据”包含混合请求的部分证据，不等于每道题均可完整作答。例如已知稳定事实与不可得实时状态同问，应交付稳定证据并说明实时部分不可用。

故事与来源均为人工合成 gold，完成事件有明确的 fixture 来源、参与者与执行状态，不是采集真实用户私人经历。所谓“真实运行”指生产代码、SQLite、ONNX embedding 和 provider prompt 构造真实执行。质量脚本按固定状态装入 current/historical/planned/forgotten 对照，不自行完成所有生命周期操作时序；真实更正/遗忘及派生失效的执行证据来自相应集成测试和独立维护基准，不能只凭这里 deleted 行被过滤就宣布整个遗忘闭环已验证。

独立留出由未读取实现和开发集的另一评测 Agent 创作，其原始 source 文本和 hash 保留。编写者未见生产代码不等于外部第三方盲测，也不证明真实用户分布泛化。自动检查只保证声明的 family ID 不交叉，语义模板是否重复仍需独立人工审查。若看过留出失败并据此修复，相应案例必须转为回归，不能继续声称未见。

`validation` 和 `holdout` 是工具中的稳定 split 标识。前者已在开发阶段用于诊断；后者在 `f7a4e23` 首次冻结评分后也已用于诊断。文件名或历史元数据里的 holdout 不会恢复其未见资格。独立比较只使用某个独立数据版本的首次冻结运行；后续重跑必须显式标为回归。

开发/验证 v2 仅修正三条无 metadata 旧记忆的 source：改为实际旧系统授权回读的 `explicit_user_request` + `user_confirmed`。问题、正文和 gold 不变；v1 原始数据与第一版失败结果一起保留。这个输入修正带来的变化不能全部归功于新算法。留出未作此更改。

独立留出的首次启动另暴露了数据合法性错误：作者原始两条 forgotten 记录使用 `valid_from == valid_until`，新旧 `EmotionalMemoryEntry.validate` 都拒绝零时长有效区间。五路线全部在第一故事构造前失败，评分查询为 0，没有检索或生成结论。原始作者 JSON、旧 fixture/manifest、五份失败日志和逐字段 diff 完整保存在 `final-holdout-300/`。

可执行交付版放在 `tests/fixtures/ondemand_memory_v2/`，两条已删除记录只把 `valid_until` 改为 API 的“无结束边界”哨兵值 0，`deleted=true` 保持不变，所以任意时间仍不可用。正文、queries、gold、forbidden、期望路由/状态未变；32 条来源通过实际 Entry 预检。新 holdout SHA 为 `c9c5c37f5c839f3c259f9a038563d24f1ee1ffbc01b54584ae3575cd3265695e`，可执行运行目录为 `final-holdout-300-v2/`。这是评分前的 schema 适配修复，不是按留出答案调参；第一次失败仍计入实验记录，不宣称全过程一次成功。原目录没有在正在执行的规模实验中被覆盖。

### 数据覆盖

- 普通闲聊、通识与创作，无需长期记忆。
- 明确事实、人物关系、同主体错误字段、来源别名、单值历史与当前事实。
- 多轮指代，包括明确对象与歧义对象。
- 有事件来源的共同经历、计划、遗忘、未知原因与未知参与者。
- 任务经验的应用、版本、前提、失败、成功及尚未执行计划。
- 外部实时状态不可用；稳定事实与实时状态、事实与经历的混合请求。
- 旧无 metadata 事实兼容、不同 owner/角色/游戏 scope 的近似诱饵。

干扰池由日常动作、地点、物件、状态组合生成，正文约几十至一百字符。虽然比八条重复模板丰富，它仍是人工合成压力集，不能代表真实十年存档的主题密度。脚本保存真实正文长度分布、数据库字节数和每个档案分母。

### 时钟基准不能混用

实际桌面控制器的 `self.now` 来自 `logical_time_from_state`，是从存档状态累加的逻辑时间，**不是 Unix 秒**。把它解释成 1970 年附近的日期，或拿它直接比较一个 2026 年日历时间，都会产生错误的历史过滤。第二轮因此把时钟语义变成显式合同：服务保留旧宿主的 `time_basis="logical"` 默认；日期已知的离线评测显式选择 `time_basis="unix"`。Router 的独立默认是 unix，但桌面服务必须传递其真实 time basis。

逻辑时钟下，包含明确年月日、月日或月份窗口的检索会返回时间未解析/证据不足，不猜测保存日期，也不私自改写旧存档时间。Unix 模式使用调用方 now 解析日期/月份半开窗口；没有足够时钟信息也应拒绝伪造日期。相对历史的事件检索和精确日历过滤应分别说明。

时间未解析是单个 intent 的状态，不等于人物指代不明确。混合请求中不能因为一个日期无法解析就停止另一个当前事实查询；这两类不足在 trace 和生成提示中分别记录。

本轮日历合成数据库实验只能证明 Unix 合同的检索行为，**不能证明实际桌面已具备完整日历回忆能力**。后续仍需为新事件保存墙钟、事件时间与记录时间，并设计不制造旧时间的迁移：旧逻辑值保留，无法恢复的旧日期标为未知，显式记录两种时间轴及查询时的可用性。

### 下一独立数据版本的冻结要求

独立作者应拿到公开存储/来源合同，而不是实现里的规则或开发题目。预检须在候选首次评分前完成并留日志：实际 `EmotionalMemoryEntry.normalized().validate`；合法非零有效区间；正文的日期与事件/有效时间一致；共同经历的角色、参与者和完成状态；任务执行状态与自然语言结果分开；每个 query 的 scope 与授权来源一致；别名能从原文获得依据。新档案的临时状态不得自动改成用户个人事实。

预检只验证数据是否合法，不运行检索来选择“系统答得对”的问题。若发现数据错误，冻结新版本并记录逐字段 diff；已经有候选评分的版本仍永久保留，是否还能称未见取决于是否看过题目或错误并据此调参。正负例、gold、禁止来源和时间期待不能在看过分数后悄悄调整。

运行完成还须校验最终 artifact 的行数、状态、source hash 和 manifest hash 一致。控制台打印 complete 不能替代落盘检查；遇到只有中间 checkpoint 的文件，应保留并重跑到新的完整文件，不补造缺少的查询。文档中的“未执行”只在真实执行结果存在并通过此完整性检查后才能更新。

## 3. 五路线与公平比较

| 方法 | 生产路径 | 长期记忆资格/候选 |
| --- | --- | --- |
| `none` | 相同 Persona/近期上下文，经实际 `ExpressionRequest` | 不读取长期证据 |
| `lexical` | 固定旧源码的完整快照、资格过滤、`rank_memories`、`finalize_recall` | 旧系统完整候选；不使用新候选短名单 |
| `bge_rrf` | 同一旧源码 + 实际 BGE + 既有 RRF | 同一旧完整候选 |
| `routed` | 新 `prepare_retrieval` + `retrieve(layered=False)` | 按需路由、结构化过滤、充分性闸门 |
| `layered` | 新 `prepare_retrieval` + `retrieve(layered=True)` | 同上，并按需提供 L1 摘录或 L2 来源 |

旧源码固定为本地前置一致性补丁提交 `299a0aa568c90525e6a6a90ce01dbbf80bfaefcb`，它基于远端 `238f361c856584c7f93cc15dca5cbf5a387393e8`。远端提交、旧前置包和本轮候选是三个状态，不能混为一个已发布版本。

开发诊断的 `source_commit` 是当时 HEAD，不会包含尚未提交的工作树修改；精确候选以同份结果的 `source_sha256` 为准。正式结果也保存全部生产文件 hash，并在进程结束再次核对。交付后的本地提交、补丁或代码包应与这些 hash 对照，不能仅因为两个工作树 HEAD 相同就认为生产实现相同。

每个方法/规模独立子进程，保存 source hashes、数据 hash、脚本 hash、模型名称/固定 revision、依赖与环境。统一 top-k=4、实际表达上下文最大 6000 字符；新检索预算同设为 6000；provider builder 最末上限均为 8192 字符。新 API 的生产默认检索上下文预算仍为 4000，本轮 6000 是为了和固定旧系统做等预算比较，不能把最终成绩不加说明地视作全部默认配置下的结果。第一版词法诊断使用过新默认 4000，作为开发失败记录保留，不用于最终预算一致的性能结论。

同一方法可以复用其自己的相同干扰项向量；方法之间不共享候选或检索结果。实际索引重建、编码数和热查询分别记录。不能把新路径冷索引耗时偷偷丢掉，再与旧系统全路径比较。

第二轮修复了旧 `Entry` 对嵌套 JSON `metadata.fact_value` 的静默丢失。因此相同原始输入经新旧代码归一后，canonical corpus 有时会不同；这既不能藏起来，也不能为了让 hash 一致而手工给旧基线补上它本来没有保留的数据。新脚本同时保存：

- `input_corpus_sha256`：作者原始行与同一生成规则的干扰项，在任何 `Entry` 规范化之前计算。
- `source_text_corpus_sha256`：规范化后的 ID、正文、标题、owner、角色、scope、时间、撤回状态等所有非 metadata 字段。
- 原有 `corpus_sha256`：完整 canonical 行，继续如实反映规范化差异。
- `canonical_without_fact_value_sha256` 与逐字段 `normalization_changes`：确认差异没有扩散到其他 metadata，记录旧实现具体丢失了什么。

汇总器要求前两层和预算一致，也要求除 `fact_value` 外的 canonical 字段一致；只有可逐字段解释的旧嵌套值删除/筛除才允许作为本轮规范化修复进行比较。任意值替换、正文或时间/权限变化、数据用途在方法间不一致仍会拒绝汇总。旧 f7 artifact 没有新 hash，继续使用原先的严格 canonical 完全一致审计，不追补虚构字段。真实新旧 `Entry` 独立进程验证位于 `corpus-normalization-contract/`。

若新结果包含这种差异，应明确称为**同输入下完整记忆管线的升级效果**，不能将全部收益归于检索排序。两条路径仍使用相同 questions、gold、forbidden 和来源正文，评分本身不因此放宽。

## 4. 指标定义与防止“全拒绝”作弊

脚本分别记录候选命中、`ExpressionRequest` 中的来源，以及 provider builder 最终字符串中幸存的来源。最后一层的 `persona:`、`emotional_memory:` JSON 行从真实输出重新解析；不能拿预算裁剪前的 ID 计最终交付。`retrieval.selected_memory_ids` 中只出现 ID，没有具体证据正文，不计成功交付。L1 的具体 claim 与 source ID 同时存在才计入来源交付。

`resolution_evidence` 是别名绑定的辅助来源，不刷目标答案召回分；其正文仍纳入遗忘、禁止来源和跨角色泄漏检查，另计来源覆盖/fingerprint。实际 provider prompt 文本和 SHA 均保存，生成评测入口优先重放该字符串，避免用未来代码重建后悄悄改变条件。

| 指标 | 分子/分母或算法 | 说明 |
| --- | --- | --- |
| Route exact | 预测 route 集合等于 gold 的查询 / 全部新路由查询 | bounded 是明确的回退，不伪装成精准分类 |
| Unnecessary retrieval | 不需要长期记忆却有检索调用的查询 / 全部无需长期记忆查询 | live 外部读取不等于全库记忆查询 |
| Recall@4 | 每题 gold 中进入候选结果的比例，再按可回答题平均 | 空 gold 不计为 100% |
| Delivered recall | 每题 gold 中真正交付正文/有来源概览的比例 | 防止只报告 retrieve 返回 |
| All gold delivered | 全部必要来源已交付的题 / 所有有证据题 | 多跳/混合题可能只得到部分证据 |
| Supported delivery | 必要来源正文完整匹配、L1 fingerprint 正确且没有 forbidden 来源的题 / 有证据题 | 比 ID/任意正文交付更严格；不会把正确 ID 配错误正文计为有依据交付 |
| Multi-evidence / follow-up / mixed delivery | 分别在多来源、多轮、混合意图有证据题中，完整且无禁止来源的交付数 / 对应题数 | 这些是证据交付，不是模型多跳推理答对率 |
| No-answer injection | 完全未知题中交付任何长期证据的题 / 完全未知题 | 与普通闲聊误注入分别理解 |
| Answerable zero evidence | 有证据却一条没交付 / 所有有证据题 | 与误注入指标并报，不能靠全拒绝获胜 |
| Forbidden injection | 交付禁止来源的题 / 全部题 | 另报结构化错项、旧事实、计划和遗忘内容 |
| nDCG@4、MRR | 二元 gold 相关性排序 | 本数据没有人工 0–3 分级，不谎称使用了分级标签 |
| L1 source coverage | 有源 claim / 全部概览 claim | 生产入口仍负责来源版本/撤回验证 |
| L1 extractive entailment | 正文可在声明来源中逐字找到的 claim / 全部概览 claim | 只评价本轮摘录合同；不是通用语义蕴含模型 |
| Persona config/delivery | 相同配置 hash 未变、真实 prompt 含相同核心 hash | 不等于实际语言行为稳定 |
| 时间/内存/Token | 每阶段 p50/p95/p99、峰值 RSS、实际相同 tokenizer 计数 | BGE tokenizer 仅作为统一长度代理，不是回答模型计费 Token |

输出保留 query、history、gold、forbidden、实际路由、决策原因、源 ID、完整 prompt、失败和各阶段耗时。错误请求保留分母。脚本对同故事成组做配对 bootstrap，区间只描述合成故事集的稳定性，不能推断真实用户总体。

Gold 标注回答所需的最小来源集。一个额外的真实相关片段可能降低二元 precision/nDCG，但并不自动等于虚构或错误事实；确证禁止内容由 `forbidden_ids`、时间/范围和源状态另查。相应地，`structured_wrong_injection` 指精准事实问题中交付了非 gold 的结构化字段，不能被引用为“模型说错事实的比例”。

## 6. 规模、性能和维护测量

质量主矩阵预先确定为 300 条/story，三个 split 共 192 问、五路线。3000/10000 的质量扩规模子集在最终运行前冻结为 `d02`、`d06`、`d08`：分别覆盖关系字段、真实共同经历、任务经验，共三个独立档案、18 问，每种规模仍运行全部五路线。这个子集不是全量 holdout 的扩规模结果；选择和 hash 保存在 fixture manifest，不能看到最终分数后换题。

每个故事重新建立独立真实档案，所以新路径的 generation 变化会按生产契约清理向量；冷索引不能凭空免费复用其他用户的档案。旧路径允许复用相同干扰项的 passage cache，旧初始 prepare 的耗时单独记在 story 记录，新路径的冷准备计入首次实际需要语义的查询。统一比较时须同时展示 setup/cold 和 warm，不能只拿新热查询与旧冷构建比较。

新生产 embedding batch 最终为 64，固定旧源码为 256。模型、revision、CPU、线程和查询保持相同；batch 差异属于明确的实现变化，相关资源测量会注明，不能被误写为纯检索算法收益。存储与语义维护另有全规模独立真实数据库基准，测量冷重建、热读、纠正、遗忘和增量编码。

质量脚本的 `index_warm` 严格指本次 passage 编码数为零，它也包含根本不需要语义索引的 fact/chat 路径；不能一概当作“语义索引已完全驻留”的热缓存样本。重启从 SQLite 恢复向量的时间要单列为持久缓存恢复，不能与首次编码或纯内存命中混在一起。此前 RAM-only 的 batch64 三规模结果保留为基线；持久向量投影另出跨进程 reopen 证据，不覆盖旧文件。

三者不得混淆：旧快照读取/排序/写回的端到端时间；新索引准备和按需查询时间；实际 LLM 请求时间。第三项本轮无请求时保持 `not_run`。CPU 并发争用下的开发诊断耗时不作为最终性能承诺。

### 真实跨进程向量复用

`incremental-embedding/persistent-embedding-performance.json` 保存默认同 SQLite 持久向量投影的完整三尺度结果。每个规模使用三个独立进程：首次真实 BGE 构建；重新打开后读取、更正和遗忘；再次打开并验证撤回及无重复 passage 编码。第三进程将 passage 编码入口设置为“调用即抛错”的探针，查询 embedding 仍然真实运行，复用的是首进程产生的实际 BGE 向量，没有用随机向量或返回金标的 Mock 替代。

| 条数 | 首次编码与首问，不含加载模型 | 第三进程恢复与首问，不含加载模型 | 加模型加载后的恢复与首问 | passage 编码数：首次/恢复/更正/遗忘 | 冷建后 DB |
| --- | ---: | ---: | ---: | --- | ---: |
| 300 | 4540.114ms | 19.284ms | 448.446ms | 300 / 0 / 1 / 0 | 2.984MiB |
| 3000 | 42971.000ms | 122.898ms | 524.805ms | 3000 / 0 / 1 / 0 | 28.328MiB |
| 10000 | 135701.704ms | 384.213ms | 769.254ms | 10000 / 0 / 1 / 0 | 94.082MiB |

这里的约 0.77 秒是模型加载+向量恢复+首次语义查询，不是整个桌面应用启动时间，也不含生成模型响应。首次万条记忆的批量编码仍有明显成本；普通 fact/chat 路由可以跳过这一模型路径。10k 另一独立 reopen 进程测得更正写入 4151.678ms、遗忘写入 2503.046ms，说明持久向量没有消除权威 JSON 文档写入的 O(N) 成本。

模型是固定 revision 的 `BAAI/bge-small-zh-v1.5`，实际 512 维 float32，CPU 两推理线程、batch64；10k 向量本体 20,480,000 字节，另有矩阵缓存副本。每阶段有 3 条 warm 查询，可报告其 p50/最大值，不能推定 p95/SLO。实验协调避开重型并发，但没有独占 CPU，也没有模拟 Windows 磁盘、断电或多设备。RAM-only batch64 和更早 batch256 文件继续保留为历史对照。

第二轮 `1eef5cb` 另外重跑 **10k** 三个独立进程，证据是 `incremental-embedding/round2-10000/`：首次构建 **145.897s**；重启首问 **385.531ms**、含模型加载 **776.065ms**；第三进程首问 **370.950ms**、含模型加载 **738.174ms**，两次重启都编码 **0** 条旧 passage。更正权威写入 **3834.051ms**，随后语义更新 **68.425ms/编码1条**；遗忘写入 **2720.570ms**，随后 **49.588ms/编码0条**。冷进程 RSS **458.668MiB**，第三进程 **248.754MiB**。源码和 profiler 前后均未改变。

这个追加组仍是合成档案，warm 仅 3 问、写操作每类 1 次；不能从它推导总体 p95。300/3000 的持久缓存数据仍属于第一轮历史检查点，不能将它们与第二轮 10k 拼成“第二轮全部三尺度已重跑”的一张表。两轮冷构建差值也不能单独归因于算法变化。

推荐复现实验：

```bash
python tools/eval_ondemand_memory.py \
  --baseline-root /path/to/frozen-299a0aa \
  --dataset-dir tests/fixtures/ondemand_memory_v2 \
  --model-cache /path/to/bge-model-cache --local-files-only \
  --sizes 300 --splits development validation \
  --output-dir artifacts/ondemand-development
```

最终候选冻结后，再以新输出目录加入 `--splits holdout`；禁止覆盖已见过的实验目录。`--no-semantic` 是明确的开发消融，不能与 `bge_rrf` 方法同时使用。

预声明的扩规模命令：

```bash
python tools/eval_ondemand_memory.py \
  --baseline-root /path/to/frozen-299a0aa \
  --dataset-dir tests/fixtures/ondemand_memory_v2 \
  --model-cache /path/to/bge-model-cache --local-files-only \
  --sizes 3000 10000 --splits development --story-ids d02 d06 d08 \
  --output-dir artifacts/ondemand-scale-fixed-subset
```

如果运行中生产源码 hash 改变，结果保留但标记 `source_changed_during_run_do_not_compare_as_frozen_revision`。这类结果只作诊断，正式五路线比较需要源码稳定。最终独立留出评测后不能继续根据其失败调参并将重跑称为首次未见评测。

最终结果通过独立的只读汇总入口生成表格与 bad case 清单：

```bash
python tools/summarize_ondemand_memory.py \
  --input-dir artifacts/ondemand-final-300 artifacts/ondemand-scale-fixed-subset \
  --output artifacts/ondemand-final-summary.json
```

该入口要求五路线齐全、相同查询集合、每故事输入和来源文本 hash 相同、相同上下文预算、生产源码在运行内及两次 campaign 间稳定。canonical 差异仅允许上文明确记录的结构值规范化修复；旧数据继续严格核验 canonical。它拒绝不完整或其他条件不同的比较，保留运行错误的查询分母。汇总 JSON 保存所有阶段统计和完整 bad case 引用，Markdown 只展示必要主表，不能用人工挑出的成功行替代原始记录。

## 7. 与 13 套计划的衔接

| 既有套件 | 本轮对应 | 仍需后续执行 |
| --- | --- | --- |
| M01 抽取与写入 | 沿用既有写入契约；本脚本人工授权录入金标事实 | 1200 source episodes 的真实抽取扩大集 |
| M02/M07 生命周期 | 存储/索引/来源撤回的生产回归与维护基准 | 更大随机操作、崩溃/并发/恢复分布 |
| M03 检索 | 本轮五路线、路由、无答案、交付与规模对照 | 100 个档案/1000 问的人工审阅扩充与真实反馈 |
| M04 章节/共同经历 | 来源摘录的覆盖、蕴含和重复计数 | 更丰富多跳、跨阶段巩固及真实模型摘要 |
| M05 端到端模型 | `not_run`，保存可供运行的输入与评分分母 | 同模型同预算真实生成、人工盲评与来源审计 |
| P01 人格 | 配置与 prompt 交付验证 | 实际语气、观点、亲疏分寸、未知表达的盲评 |
| P02 主动陪伴 | 核心保留，未把任务提醒当人格 | 日志/时钟回归及 14–28 天体验研究 |
| S01 存储/性能 | 300/3000/10000 真实 SQLite 与 BGE | Windows 实机、故障盘、10 万条和多客户端 |
| X01/T01/D01/D02 | 接口与权威分工保留 | 手机、外部执行器、多端同步和长程真机任务 |

下一阶段真实模型比较必须复用本轮相同有效来源和预算，另外冻结答案正确性/虚构经历/恰当未知/人格行为标注。模型自然地表达未知是生成行为；本轮的结构化 unknown 和 prompt 指令只能提供必要条件，不能替代该验证。

## 8. 由真实失败驱动的下一版质量工作

本节是后续开发与评测要求，**不是本轮已经实现的第二套检索框架**。默认集成的只读审查见 `final-round2-sealed-300/default-integration-review.md`：当前 `build_context` 已默认进入新路由，兼容方法存在但未提供已验收的策略开关。质量门槛失败应阻断“整体记忆质量升级完成”的发布结论；存储和生命周期证据可以单独验收。

| 需要解决的层 | 可泛化的实现方向 | 验证方法和保留的负例 |
| --- | --- | --- |
| 问题拆分与路由 | 区分真正请求、给出的前提、解释、否定约束和寒暄；确定性简单路径继续零模型调用，复杂请求可进入有预算的语义解析 | 按语法族独立划分；评估 route exact 之外的意图覆盖/漏拆/误拆；“不要把另一人的事实算给我”不能产生新的回答主体 |
| 开放属性 | 从档案实际字段、值类型、对象和原文构造动态属性目录；数量、单位、位置、顺序等作为类型约束，不按故事新增字段白名单 | 相同主体的多个数值/单位、同物件错误属性、同字段其他主体；不能把任何数值都视为数量答案，也不能因字段名字陌生拒绝原文明说的事实 |
| 候选与充分性 | 保持 owner/角色/scope/有效时间/撤销硬过滤；在其后研究可校准的交叉编码器或有界模型证据验证，返回原文 span/来源 ID，逐项核验而非直接生成新事实 | 原候选、被拒 gold 和扩展候选分层记录；对照真实召回损失与误注入，按查询类型画接受/拒绝曲线；不能将 cosine 当正确概率 |
| 多轮指代 | 用有界的对话指代状态保存最近已证明的主体/物件、待问字段、时间模式和来源 fingerprint；这是短期状态，不写成长期用户事实 | “那现在”“我的那只”“这一版”及换主体/换字段；删除、更正、角色切换和 epoch 更新后应撤销旧绑定；不能以无依据的 assistant 文本建立事实 |
| 任务经验 | 用实际应用/版本/操作记录目录识别任务，不靠固定部署/安装词表；把当时完成证据和现在前提是否满足分开 | 同应用不同版本/设备、未提供前提、相反前提、失败和计划；回忆过去步骤不等于保证现在执行成功 |
| 人格与未知体验 | 让无依据、来源已撤回、对象不明确、实时服务不可用和仅部分证据成为不同体验；人格核心保持稳定 | 实际模型 M05/P01 盲评：事实正确、不过度拒答、不虚构共同经历、自然地表达未知、恰当澄清分别评分；不以 Persona 配置送达代替行为评价 |

对于复杂路径，语义模型只能帮助理解请求或判断当前候选是否支持请求；它不能授权跨作用域读取、恢复已忘内容、创造人物别名，或用自身生成内容作为共同经历来源。若模型输出引用 span，必须能在当前有效原文中逐字定位，来源版本也必须在最终交付事务中重新认证。

每轮修复先跑全部已见回归，并报告**丢失的旧正确题**，然后在新冻结语言/故事族上首次评价。至少保留三组并列结果：不需要回忆时是否安静；确有证据时能否完整交付；无依据时是否不注入。单项精度变好、开发集满分或索引变快，都不能替代完整的长期伙伴体验结论。实际目标规模与门槛继续沿用 13 套/28 指标原计划，不根据本轮低分下调门槛。
