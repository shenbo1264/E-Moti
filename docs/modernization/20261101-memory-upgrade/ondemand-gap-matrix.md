## 下一步顺序

1. 在隔离工作树核对 main/PR、先决包和本轮变更；保留发布阻断，不覆盖正在修改的 UI/手机代码。
2. Codex 首先分离资格硬拒绝与语义未证实，补开放属性候选、多轮焦点和有预算的证据验证，并校准召回/误注入双门槛；不要继续靠针对样例增加词表。Claude 并行接入状态与依据展示，完成更正/遗忘、安静与合理未知体验。
3. 接真实模型跑答案与人格行为矩阵，记录原始输出、模型版本、token/成本。冻结后才评分新的未见故事；看过并用于改动的数据改列为回归。
4. 补桌面真实时钟迁移、现实变化/纠错的双时间语义、全文 claim/span 来源，以及更完整的任务前提/执行 run_id。
5. 根据秒级写入成本立单权威行式迁移 ADR，保留事务、旧 API 适配、备份恢复与撤销证据；完善有预算的全历史巩固。
6. 核心契约和质量通过后，再推进手机共享人格/事实、离线撤销同步和长程任务互通。

“可靠”在这里由明确的不变量构成：事实有来源、当前与历史分离、未知可表达、撤销可传播、失败可观测、资源有预算。它仍需真实模型和长期使用验证，不能以几个单元测试宣称长期人格已经完成。
