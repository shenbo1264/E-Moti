# 需求、完成标准与依赖

## 1. 产品目标

E-Moti应持续理解用户、记住真实共同经历、保持角色身份和表达习惯，并在授权范围内主动参与。
用户可以关闭工作、游戏、观察、移动端连接，继续完整使用桌面陪伴。
手机目标是Android/HyperOS、iPhone/iOS和华为原生HarmonyOS手机。

当前工作不重构Relay，不开发Body固件，不替换角色资产，不改变既有存档归属。

## 2. 核心需求

| 编号 | 要求 | 可执行验收 |
| --- | --- | --- |
| MEM-01 | 同一事实的摘要、结构值和派生表达一致 | 聊天保存→相册更正→主动台词；旧值及其同义陈述不能出现 |
| MEM-02 | 含义变动可被版本/指纹识别 | 单改主体/字段/值会失效；访问计数变化不造成无意义重建 |
| MEM-03 | 更正限定目标主体与字段 | 注入错目标候选必须拒绝且原事实不变；相关人物/本人一致 |
| MEM-04 | 整批提议无隐式互斥状态 | 同批冲突单值不同时生效；多值偏好仍能共存；歧义明确处理 |
| MEM-05 | 长期可连续更正 | 数百次更正、重启、忘旧id沿链处理；不因复制祖先来源达到8条而失败 |
| MEM-06 | 权威记忆不因展示上限丢失 | 超300条，旧置顶/确认项存在并可纠正/遗忘；查询/缓存可以限量 |
| MEM-07 | 老存档正确升级 | 普通旧事实保持；旧更正造成的矛盾结构修复/降为笔记；旧派生不被错误重签 |
| MEM-08 | 完整提取多片段 | 规则返回consumed spans，补抽剩余部分；不因第一句命中漏记后半句 |
| MEM-09 | 主体、字段、时间明确 | self、多个相关人物、别称、当前/历史/计划区分；不以关系标签等同实体ID |
| MEM-10 | 共同经历必须发生过 | 计划/开始/完成/核验/用户接受有不同状态；模型叙述不能自动生成完成事实 |
| MEM-11 | 巩固可追溯和撤销 | 每个事实性claim对应源事件；源纠正/遗忘后重建或撤销相关claim |
| MEM-12 | 遗忘覆盖实际出口 | 画像、章节、metadata、向量、history、inflight、TTS、手机弹窗/缓存/outbox |
| MEM-13 | 用户能管理自己的记忆 | 来源、主体、时间、版本、作用域；纠错/现实变化/遗忘/物理删除语义清楚 |
| MEM-14 | 一套权威存储 | 语义索引可重建、不可绕过当前状态；不同时运行两套相互覆盖的事实库 |
| PER-01 | 核心人格不被预算静默删掉 | 合法最大persona、最终prompt、修订prompt均保留身份/边界/版本/hash或明确失败 |
| PER-02 | 人格配置与行为分别验收 | 配置hash、实际交付、模型风格、情绪反事实、多轮/跨模型独立计分 |
| PER-03 | 有限互动适应 | 有来源、强度范围、回退/用户锁定；不因一次聊天重写核心身份 |
| PER-04 | 主动性符合真实时间与活动 | quiet/cooldown/date/presence分域；没有返回事件不宣称欢迎回来 |
| SYS-01 | 所有入口同一对话语义 | desktop/host/album/plugin同输入最终状态一致；模型提取与语义准备不分叉 |
| SYS-02 | 任务与事实分层 | Relay权威状态、任务journal、临时屏幕观察与长期用户事实各有作用域 |
| SYS-03 | 失败可定位且不掩盖 | input→candidate→mutation→eligible→rank→prompt→draft→review→publish trace |
| SYS-04 | 兼容旧角色、插件与存档 | 旧pack/保存目录/API不随意改变；迁移幂等、失败可恢复、撤销不丢 |

## 3. 手机与任务需求

| 编号 | 要求 | 完成标准 |
| --- | --- | --- |
| MOB-01 | 自己提交与第三方失效可区分 | input_version/committed_version/request_id；自己遗忘成功不误判Stale |
| MOB-02 | 全部派生UI与晚到响应失效 | 来源弹窗、编辑稿、通知/TTS、unpair后回填均有generation/epoch检查 |
| MOB-03 | 日常连接和同步 | QR/TLS/设备撤权、有效历史分页、事件游标/缺口恢复、断网重连 |
| MOB-04 | 独立聊天和待同步候选 | 手机断电脑时使用获准最小投影；重连先撤销后合并；不静默双写权威 |
| MOB-05 | Android真实执行 | 本机观察/动作/验证、接管/取消、同App焦点、锁屏/权限/ROM矩阵 |
| MOB-06 | 观察来源可分辨 | 自述/分享/使用元数据/通知/节点/截图/推断分开；短期缓冲默认不入人格 |
| MOB-07 | iOS/鸿蒙原生适配 | 共用协议；按实际SDK/签名/系统权限真机验收，不继承Android特权假设 |
| TASK-01 | 幂等、恢复、取消与预算 | durable outbox、command lookup、events、cancel ack、deadline和真实后置条件 |
| TASK-02 | 长程推进与汇报 | 1/8/24小时、重启/失联/PC休眠；阶段证据和产物可核验 |
| TASK-03 | 任务经验复用 | 环境/应用/版本/前提/成功失败证据；经验过期/反证，不污染人格和用户事实 |

总开关保留，同时使用系统实际可提供的分能力授权和来源范围。屏幕内容不获得用户指令的权限。
Root/越狱不是产品基础要求；ADB增强执行明确标记额外配置。

## 4. 性能要求与规模

当前典型模式按一个用户、一个活跃角色、桌面常驻、移动端按需连接设计。
性能目标应在固定硬件/数据长度/缓存/依赖版本后冻结。下面是目标范围，不是测量结果：

- 日常热记忆路径目标：几千条有效记忆时，本地资格过滤+检索+上下文构造p95控制在200ms量级内。
- 到一万条时先测实际瓶颈，再决定规范化表、词项索引、向量矩阵或ANN；
  不因记录数达到某个整数就强制引入服务。
- 冷启动、首次模型下载、全量重编码、热查询分别报告；不能以热查询代表首次使用。
- Qt主线程单次长阻塞应拆出；目标p95<50ms，实际UI与桌宠体验另测。
- 更正/遗忘的提交与撤销优先于后台巩固；在途编码结果不能恢复已撤销内容。
- 按阶段记录tokens、p50/p95/p99、RSS、存储大小、CPU、成功轮成本。
- 本轮去掉300条静默截断解决数据正确性；单文档全量读写仍需规模化改造。

## 5. 质量目标

目标在密封评测前确认，不得看结果后改门槛求通过：

- 错主体覆盖、跨角色污染、遗忘旧内容进prompt、迟到响应恢复撤权数据：关键release suite零例。
- 写入precision>=98%、recall>=90%；同时检查控制事实保持，不能通过不保存达标。
- 检索Recall@4>=90%、无答案误注入<=5%；分语义改写/同名/时间/无答案报告。
- 有依据回答正确率>=95%；事实、语气、有用性、拒答分别计分。
- 人格核心维度平均>=4/5，角色分组不低于3.5/5；人工盲评及多次采样。
- 任务成功由业务后置条件确定；“模型说成功”不能计成功。
- 独立样本、故事内重复、设备重复分清；保留全部失败、取消与fallback。

完整13套评测和28指标已随本包提供，见[evaluation-plan.md](evaluation-plan.md)及机器可读JSON；本轮真实检索诊断只是该计划中的一项开发实验。
