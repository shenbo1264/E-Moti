# 面试技术说明：E-Moti 的可撤销、按需个人记忆

## 产品问题与交付边界

E-Moti 是可独立运行的 Python/PySide6 个人 AI 伙伴。它的长期价值来自稳定人格、正确的个人事实和有依据的共同经历，而不是每句话检索几段相似聊天。工作、游戏、手机观察都是可关闭的外部能力。本轮只改核心软件，保留已有角色包、用户选择、存档格式、桌面 UI 与插件接口；没有开发手机 UI、Relay 或硬件固件。

## 可以讲清楚的设计选择

### 1. RAG 是读取策略，长期记忆是状态系统

人格按版本直接加载，用户事实按主体、字段和有效时间查询，经历采用词法/语义混合检索，最近对话有界保留，任务经验按应用、版本、前提和真实结果隔离。实时任务进度来自外部权威接口，不能用旧聊天冒充当前状态。

因此，一条记忆必须同时解决来源、置信度、生命周期、修订、有效时间和用户控制；向量相似度只能提候选。用户问牙医姓名时，吉他老师即使 cosine 很高也不能成为答案。没有证据时返回 unknown 是正确行为，但也要同时测真问题被误拒的损失。

### 2. 在一套权威数据上增量升级

保留既有 `memory_state.payload` schema 2 JSON 为唯一权威，在同一 SQLite 事务内维护结构化事实、实体别名、来源、词法、章节及版本游标投影。向量也存为同库派生表，可以从有效来源重建。

这避免并排运行 Mem0、Graphiti 和旧记忆各自写入事实，降低存档迁移风险。代价是更正和遗忘仍要写完整 JSON。真实万条规模更正仍为秒级，所以后续优先论证行式权威迁移，而不是先加一个向量服务掩盖写入瓶颈。

### 3. 先决定需要什么证据，再查找

本地路由区分 chat、fact、episode、task、live 和 bounded 六类。简单问题不用额外模型；复杂句式目前依靠有界规则、多意图拆分和最近有效用户问题的指代继承。默认每意图最多 64 个初始候选、全问题最多一次额外 64 候选展开、最多 4 个意图和 8 条展开来源。

候选依次经过身份/角色/scope/时效/撤销过滤、主体字段匹配、话题和所需细节检查、来源最终认证，再进入表达上下文。存在事实但缺所问细节、预算裁掉依据、存在歧义或冲突，标记 insufficient；没有合法匹配证据才是 unknown。实时接口不可用是 external_unavailable，不能说任务失败。

### 4. 把“忘记”作为跨层不变量

纠正或遗忘不仅修改正文，还要撤销结构化字段、别名证明、章节、画像引用、向量缓存、最近对话和在途生成。采用来源指纹、generation/revision 与 `context_epoch` 分工：指纹识别具体语义版本；revision 驱动投影增量；generation 处理重建；epoch 使旧上下文和在途答案失效。

本轮真实复现过一个旧 writer 漏洞：直接删改来源让 index revision 变化，但未推进 epoch，旧答案仍能发布并重新进入历史。修复在底层事务同步补进 epoch，既覆盖旧写入，也不让普通访问计数误触发整轮撤销。另补实时证据 TTL 的最终发送检查，因为它可以在没有任何本地事实变化时过期。

### 5. 分层记忆必须逐条有依据

L0 是轻量目录，L1 是带来源指纹的摘录概览，L2 是原始存储卡片。概览替代对应原始卡片，避免重复占预算；详细追问再通过 ID、指纹、epoch 读取原始来源。L1 不生成新事实，旧章节自由文本不自动当证据；来源失效则先撤销视图。

一次共同事件可能同时有对话、执行和产物三个来源。计数按相连来源组而不是 source ID 数量，避免同一件事被算成多次相处。关系表达只根据有效共同事件有限变化，不从一次聊天改写角色人格。

### 6. 缓存速度需要跨进程证明

复用 FastEmbed、固定 BGE 和既有 RRF，加入增量清单、向量矩阵及同库持久缓存。模型 revision、512 维输出、编码协议、来源指纹、身份、scope 与 generation 均参与缓存校验。源更新/删除 trigger 在原事务中撤销缓存；缓存损坏降级重建，权威缺失不能凭向量恢复事实。

在当前 `1eef5cb` 的真实 BGE、真实 SQLite、独立 Python 进程中，10,000 条短记忆首次建索引及编码为 145.897 秒；重启恢复与首问为 385.531 ms，连同该次模型载入为 776.065 ms。第一次编码 N 条、两次重启都编码 0 条、更正编码 1 条、遗忘编码 0 条。完整环境、分母、RSS 和原始日志见 [持久缓存报告](persistent-vector-cache.md)。这不是桌面整机启动时间，也不是 LLM 回答延迟。

## 怎么证明效果，而不是挑一个好例子

比较五条路径：无长期记忆、固定旧词法、固定旧 BGE+RRF、新按需结构化路径、新路径加来源分层。使用相同故事档案、干扰池、top-k、上下文预算与实际 provider prompt；旧基线代码固定在 `299a0aa`。当前已见回归由开发 108 问、开发期验证 36 问和第一轮留出 48 问组成；再由未接触实现及旧数据的独立作者准备第二轮 48 问，在源码冻结后首次评分。另外预声明 18 问扩到 3,000/10,000 条；不能把这两组重复扩规模当成新语言样本。

评价最终 provider prompt 的有效证据交付，不能只评候选列表或 `ExpressionRequest`，因为最末字符预算仍可能裁掉证据。完整召回与无答案误注入同时计分；persona 配置稳定、persona 真正进入 prompt、实际生成行为三个层级分开。故事为 bootstrap 聚类单位，避免把同一故事的多个相关问题当独立样本。

最终分数、五路相同语料验证、逐项分母和未见 bad case 见 [本轮评测](ondemand-evaluation.md)。确定性测试覆盖真实 SQLite、撤销和并发协议；受控编码器只证明缓存协议，不作为语义质量证据。没有真实生成请求的回答正确性、自然未知、人格一致性和计费 tokens 均标记 not_run。旧桌面使用逻辑秒，已明确阻止其冒充日历；Unix 时间档案的日期正确性不能表述为桌面全量时钟迁移完成。

## 值得展示的失败与取舍

- 第二轮独立未见集仍未通过：完整正确证据 7/33，未知误注入 0/10，但证据召回从旧 BGE 的 0.6970 降至 0.2121。核心原因是语义排序前的字面门控与多轮路由泛化不足。对 33 道有答案题，零误注入并没有证明“会记得”。这次结果保持原样，未通过继续增关键词来改写同一批留出成绩。
- 初版严格 gate 确实减少误召回，但也拒绝旧存档中的明确原话。后来加了有界原文验证，仅在完整字面属性或相同情境/对象相符时接受，不用放开主体字段的方式挽救召回。
- 验证阶段保留宠物句式、关系职业、共同天文经历及数量字段等误拒样本；是否被通用修复影响，以最后冻结结果为准，不预先承诺清零。
- SQL 原型曾因为 FTS JOIN 顺序、非索引字段删除和错误扫描计划变慢；保留查询计划和坏例，使用索引/VM-step 回归定位具体退化。
- 缓存原型出现“编码期间只新增来源，重试却漏存旧向量”和“缓存写失败后热查询不补写”的问题，已加入待持久化集合并保留 red/green 回归。
- 源索引与向量增加磁盘和内存；后台整理目前只是有预算的近期候选，尚非全历史断点维护。10,000 条权威写入仍为秒级。没有把读优化扩大宣传成全部操作都快。

## 下一阶段如何安排

Codex 先根据最终独立结果完善歧义/语义证据证明，并用另一批新冻结故事验证；接着做真实模型答案矩阵、默认 4000 字符预算和更长真实文本，再依据写成本推进单权威行式迁移。需要模型路由时仅服务歧义路径，限定调用数、时间和失败回退。

Claude 使用 trace、依据卡和来源展开接口实现自然的“记得／部分记得／目前不知道”体验；验收纠正与遗忘反馈、合理主动性、安静模式、不虚构共同经历及人格行为。手机随后共用同一人格与事实权威，离线投影恢复前先处理撤销；Android、iOS、原生 HarmonyOS 的能力边界单独验证。

## 简历表述建议

> 主导 E-Moti 个人 AI 伙伴的记忆架构升级，在现有 Python/PySide6 与 SQLite 存档上落地按需 RAG、主体/字段/时间检索、来源化分层记忆及跨缓存撤销。建立固定旧代码的五路检索对照和两轮独立留出，发现并量化字面门控的误拒问题，保留失败以阻断不充分的质量发布。完成 300/3,000/10,000 条数据库性能对照及真实 BGE 缓存验证，使万条记忆跨进程恢复无需重新编码；真实回答和长期人格行为另行验收。

简历补充准确率时必须直接引用最终独立留出分母；不能把开发集、合成短记忆、Prompt 证据交付或单次延迟改写成线上用户满意度、真实生成正确率或生产 p95。
