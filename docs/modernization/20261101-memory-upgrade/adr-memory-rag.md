# ADR：Personal Agent记忆采用按类型读取与混合检索

状态：采用主方案，规模优化按实测推进。日期：2026-11-01。

## 本轮落地补充：按需路由、同库投影、来源分层

第二批已实现生产路径，详见 [Memory Architecture](memory-architecture.md)、[Storage](storage-index-v1.md) 和 [Retrieval Contract](retrieval-contract.md)。下面保留第一批 RAG 取舍的原因与历史基线；最新实验数字以 [本轮 Benchmark](ondemand-evaluation.md) 为准。

**决定一：继续做 RAG，但先识别证据需求。** 人格按版本直接提供；明确主体/字段的事实先查索引；经历与任务才按需做词法/语义候选；实时状态读权威接口。路由默认是轻量本地策略，简单路径不调用 LLM。歧义路径有界，无法证实时允许未知。OpenViking 官方文档支持“会话意图可生成零个或多个查询”和按概览/细节读取的设计；其当前实际实现是全局向量检索+可选重排，不能把其类名当成已验证的递归树遍历。[官方层级文档](https://docs.openviking.ai/en/concepts/03-context-layers)；[官方检索文档](https://docs.openviking.ai/en/concepts/07-retrieval)。

**决定二：规范化索引与权威拆开。** 保持 V2 SQLite JSON 是唯一事实权威，在同一事务里维护条目、别名、来源、章节和 FTS 投影。优点是旧存档/API/撤销迁移风险小，读路径实际有界；代价是完整语义写入仍 O(N)。直接将权威迁为行式表可能进一步改善写入，但必须独立证明迁移、旧接口、批量原子性和恢复正确性。本轮不同时运行另一套 Mem0/Graphiti/Hindsight 事实库。

**决定三：中文 FTS 需要实际检验。** 原生 unicode61 会把连续中文文字当词，trigram 对不足三个字符的 MATCH 有限制；本轮用安全编码的单字/二元片段与 BM25 作为候选通道，短姓名/字段用结构化索引。FTS 不负责实体正确性。原型测试还发现 FTS UNINDEXED 删除和错误 join 顺序的实际性能问题，修复及反例保存在证据目录。[SQLite FTS5 官方文档](https://www.sqlite.org/fts5.html)。

**决定四：保留成熟的 BGE/FastEmbed/RRF，不添加 ANN 服务。** 现有 BGE small 是固定模型/版本，向量是可重建缓存。新 manifest 游标维护增量，同版本复用，纠正只编码变化来源，遗忘清可见分数及受影响向量/矩阵。本轮真实向量 shape 确认中文 `BAAI/bge-small-zh-v1.5` 为 512 维，不能套用其他语言 small 模型维度；10k 的 float32 原始向量约 19.53 MiB，另有搜索矩阵副本，真实运行内存主要还受 ONNX batch 工作区影响。是否使用 HNSW 要看真实候选规模和搜索耗时，不能用它解决并非向量扫描引起的内存问题。

**决定五：L1 采用摘录式来源绑定。** 现有阶段章节可继续保存，但新的模型上下文只接受逐主张有效来源。来源失效先撤销视图，重建失败不恢复旧摘要。当前精确摘要蕴含通过文本相等/指纹检查验证；生成式文学润色、复杂事件图和长篇原文展开另做质量与撤销证明。

| 备选 | 实际采用 | 不采用整套框架的理由 |
|---|---|---|
| SQLite / FTS5 | 直接复用标准库 SQLite 与官方 FTS5 | 单进程桌面已有 SQLite，迁移和分发成本最低 |
| FastEmbed / BGE | 保留真模型与固定版本，增量准备和矩阵搜索 | 无新增模型服务；语义相似不承担事实判真 |
| Graphiti | 保留已有 Apache-2.0 RRF 适配与第三方告知，借鉴时间/来源失效 | 整体图存储会增加第二套迁移与运维；本轮需求可用现有结构表达 |
| OpenViking | 借鉴 L0/L1/L2 与按需查询机制 | 当前上游 AGPL-3.0，与本仓库约束不符，不复制源码 |
| Hindsight | 借鉴撤销派生观察、充分/部分证据和错误状态区分 | MIT 允许研究复用，但整体服务引入成本尚无实测收益 |
| Letta / MemGPT | 借鉴人格/核心上下文与归档回忆职责分离 | 不替换现有桌面宿主、角色生命周期与存档 |

许可证、源码 SHA、具体可借鉴和不可照搬的异常路径见 [本轮研究附录](ondemand-research-appendix.md)。本轮新增实现没有复制 OpenViking AGPL 源码；继承的 Graphiti 授权文件保持完整。

## 1. 决策

E-Moti需要检索增强生成。现有词法、FastEmbed/BGE、RRF和上下文注入已经具备RAG链路。
保留并完善这条链，同时按信息类型选择读取方式：

| 信息 | 主要读取方式 | 理由 |
| --- | --- | --- |
| 核心人格、作者边界 | 版本化直接提供 | 不应因相似度低而丢失身份 |
| 必须遵守的交互约束 | 有来源且当前有效的精简投影 | 不能每轮依赖偶然召回 |
| 用户明确事实/偏好 | 主体+字段+时间精确查询，语义补充 | 当前值、主体和版本优先 |
| 共同经历/故事 | 词法+向量+来源/时间过滤，必要时多条证据 | 查询常是换一种说法，且需要事件关联 |
| 最近对话 | 有界会话上下文与有效期检查 | 支持当前指代，避免每句重建历史 |
| Relay/游戏/手机当前状态 | 权威接口或短期有时效缓存 | 旧记忆不应覆盖外部当前状态 |
| 工作流和环境经验 | 作用域化经验条目/检索，复杂问题再多步查证 | 经验依赖应用版本、前提、成功失败证据 |

RAG是选证据并交给生成器的方式；它不负责决定“用户是否真说过”“现在还成立吗”“是否已遗忘”。
这些由事实结构、来源、版本、时间和宿主写入规则负责。向量索引只保存可重建表示与ID，不能成为另一个事实权威。

## 2. 为什么不把全部历史直接塞进长上下文

少量近期聊天可以直接提供；全部历史长期增长会增加输入成本、干扰和撤销复杂性。
模型能接收长上下文，不等于它能稳定使用所有位置的信息。历史研究Lost in the Middle指出相关信息位置会影响读取；
这不是对所有2026模型的统一判决，应在实际选定模型上比较全上下文与受控检索。

全文还会同时包含旧事实、纠正、引用和未发生计划。若没有状态解析，长上下文会把这些判断重新交给模型每轮处理。
保留完整存档供用户管理/回查，与每轮将全部存档送模型是两个不同决策。

## 3. 为什么不能只用向量top-k

相似度衡量文本相关，不表示事实正确或当前有效。
“本人住址”和“室友住址”可能很相似；“想去旅行”和“已经旅行”也可能很相似。
同理，已遗忘内容不能因为分数高而被召回。

主流程：

1. 校验owner/角色/来源授权/删除/有效时间。
2. 明确主体与字段的问题优先查当前事实；未知或歧义保留为未知/澄清。
3. 情节或语义问题走词法与向量召回；融合后按实体/时间/多样性选证据。
4. 最终prompt前再次解析当前权威条目并核对来源/版本。
5. 生成后验证引用、允许的表达和当前epoch；在途结果不能越过撤销。
6. 复杂跨事件或任务经验问题才允许有预算的多步查找；日常闲聊不必每次启动完整检索Agent。

## 4. 性能结构与历史测量边界

### 第一批历史检查点

以下段落描述先决补丁 `299a0aa`，不代表第二批当前代码。基线使用CPU ONNX、2线程、一个embedding工作线程，条目向量在RAM。
新条目可增量编码；invalidate会清空全部RAM向量，撤销后重编码代价需单列。
每次查询仍遍历有效条目，词法tokenize和向量相似度大致随N增长。
当前SQLite是JSON文档，读取/写回涉及全量payload，因此检索微基准不代表端到端存储性能。

第一批已将稳定上下文读取从10–11次完整事务降至2次：一致快照、事务外检索、当前来源复核和批量touch。
同机8查询对照，300/3000条短语料的build_context中位延迟分别由224/2188ms降至43/425ms；
尚未达到几千条完整本地路径p95约200ms的目标。更正和遗忘仍走原有全量文档写入路径。
数字口径与限制见[delivery.md](delivery.md)和[measured-results.json](measured-results.json)。

### 第二批当前实现

当前默认采用同库结构化/FTS 投影、增量来源清单和持久向量缓存。`invalidate()` 立即清除可发布的分数与请求状态；有效来源的同规格向量可保留，待当前指纹与版本重新认证。更正、遗忘、到期在原事务中删除受影响的持久向量；重启不必重编码全库。

当前 `1eef5cb` 的真实 pinned BGE 10,000 条首次建索引及编码为 145.897 秒；重启缓存恢复与首问为 385.531 ms，连同该次模型载入为 776.065 ms。更正仍有约 3.83 秒权威 JSON 写入，另加约 68 ms 语义准备。这一写入样本不能代替独立三次写入的存储性能中位数。首轮的 135.702 秒/379.413 ms 保留为历史结果，不冒充当前版本。不同阶段、版本、样本数必须分开描述，详见 [持久缓存](persistent-vector-cache.md)。独立 SQLite 三尺度重测以 [Storage](storage-index-v1.md) 的第二轮结果为准。

第二份独立质量留出并未通过：严格正确证据仅 7/33，证据召回 0.2121。架构的分层与生命周期收益不证明当前规则路由/字面充分性策略适合默认发布；本 ADR 的后续决策是保留同库投影与来源屏障，先补语义证据判定和多轮状态，用新的独立数据同时验收召回与误注入。[默认路径评估](retrieval-release-assessment.md)给出具体工程边界。

本轮性能报告区分：

- 下载与模型初始化；
- 首次条目编码；
- 向量热查询；
- 词法排序；
- RRF与实际上下文构造；
- 更正/遗忘后的重新准备；
- 全进程RSS与向量数据大小；
- 生成模型提取、首答、修订的额外调用（没有实际调用则不报数）。

不能给尚未运行的Windows/HyperOS延迟填估计数。
桌面端以小型CPU embedding为起点，目标设备的CPU、内存和系统版本另行记录；是否使用GPU取决于实测。

## 5. 升级质量来自哪里

| 改动 | 直接改善 | 不应声称 |
| --- | --- | --- |
| 统一事实修改与指纹 | 更正后事实/metadata/派生一致，撤销可检测 | 已提高全部自然语言理解 |
| 直接来源与修订链分开 | 长期可反复纠正、来源不丢 | 已解决实体消歧 |
| 取消300条权威截断 | 不静默丢长期记忆 | 已完成大规模性能优化 |
| 人格预算优先级 | 身份/边界实际送达 | 已证明多周人格稳定 |
| 混合检索与实体时间过滤 | 同义召回、当前事实、无关注入控制 | 向量命中一定正确 |
| 有证据的章节巩固 | 跨事件连续性和可追溯回忆 | 任意生成的故事都真实 |
| 语义提取与读者实测 | 开放域提取/回答真实质量 | 用mock代替模型成功率 |

质量是多个条件共同满足：正确形成事实、有效维护状态、选出证据、送达上下文、正确使用证据。
不能只把Recall@k当成整套记忆准确率。

本轮修复用以前失败的真实代码路径证明正确性改进；
检索诊断用真实embedding对照三条路线；
端到端生成和长期人格仍需要按后续验收独立证明。

## 6. 组件选择

- 保留FastEmbed0.9.1与固定BGE revision，继续词法+RRF。
- 不为当前单用户桌面引入独立Qdrant/Neo4j服务或并行Mem0事实库。
- 第二批已实现同库规范化投影、FTS5/BM25中文索引、持久缓存和批量向量矩阵。下一阶段依据真实误拒样本改进证据理解，并针对 O(N) 权威写入独立论证行式迁移；只在实测规模/并发需要时引入 ANN 或外部向量服务。
- Letta/Mem0/Graphiti作为具体设计和组件来源，按实际接口/许可证/维护成本复用。
- 个人事实与环境经验分开评测。任务经验可借鉴LongMemEval-V2的静态状态、
  动态跟踪、工作流、环境陷阱、前提识别，并参考其现有baseline代码。
- 复杂任务检索可采用有预算的文件/工具查询；需要比较质量-延迟曲线，
  不把编码Agent逐文件搜索放到每句陪伴聊天前面。

本轮复用记录：

| 组件 | 状态与来源 | 许可/处理 |
| --- | --- | --- |
| FastEmbed 0.9.1 | 原项目已有可选依赖，本轮实际执行CPU推理；没有修改依赖声明 | [Apache-2.0](https://github.com/qdrant/fastembed/blob/main/LICENSE)，保留既有归属与许可说明 |
| BGE small zh v1.5 | 原生产模型，Qdrant ONNX revision `46fbe35fd4374a00fee7de77dfddaeb6dd6a2c59` | [BAAI模型](https://huggingface.co/BAAI/bge-small-zh-v1.5)及[ONNX模型](https://huggingface.co/Qdrant/bge-small-zh-v1.5)标注MIT；开发包不含权重 |
| SQLite/现有V2 | 继续使用Python标准库及原有权威存储 | 没有新的数据库进程、格式分叉或框架迁移 |
| LongMemEval-V2 | 参考最新任务经验评测和已实现baseline；本轮未复制其源码 | 官方仓库Apache-2.0；未来具体复用时保留相应文件归属、许可证和变更记录 |

独立实验环境的NumPy/ONNX Runtime等解析版本记录在measured-results.json，未把它们误写成生产依赖升级。

## 7. 外部一手依据

- [RAG原论文](https://arxiv.org/abs/2005.11401)：外部检索证据与生成结合。
- [LongMemEval](https://arxiv.org/abs/2410.10813)：提取、多会话推理、时间、更新、恰当不答；索引/检索/读取分层。
- [LongMemEval-V2](https://arxiv.org/abs/2605.12493)与[官方代码](https://github.com/xiaowu0162/LongMemEval-V2)：
  关注环境经验，已有无检索、RAG、notes与AgentRunbook实现；论文标为Work in Progress。
- [Lost in the Middle](https://arxiv.org/abs/2307.03172)：历史模型长上下文位置影响，不能直接外推当前所有模型。
- [EverMemBench现版论文](https://arxiv.org/abs/2602.01313)：多人归属、时间版本、隐式相关性；补充个人/手机多来源测试设计。

本ADR采用原理与可复用方法，没有把任何论文的百分比当成E-Moti实测结果。
