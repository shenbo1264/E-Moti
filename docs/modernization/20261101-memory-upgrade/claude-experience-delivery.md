# Claude 产品与前端交付记录（2026-11-01）

分支 `claude/memory-experience`，基于 Codex 提交 `865ee1f`。未推送，未发布。

## 用户能感受到的变化

- 回忆册分成待确认、当前事实、计划、共同经历、任务经验、外部实时状态、历史事实、已更正或忘记八类。
- 每条显示状态、主体、字段、来源；选中后显示发生、记录、有效时间、版本和范围。
- 逻辑时间写成“相处第 N 天（逻辑时间）”，不猜日历日期。
- 回忆册顶部可以问一句话，走生产检索路径，显示证据状态和有来源的概览。点击调用 `expand_sources`，传 memory ID、fingerprint、epoch，界面写明这是记忆卡，不是完整聊天原文。
- 聊天后按本轮状态显示一行提示。`not_needed` 不显示。`unknown` 写明“不代表你没说过”。所有状态都不用红色。
- 修改分成“之前记错了”“现在情况变了”。另有“忘记”和“彻底删除”，确认文字写明彻底删除不覆盖备份和 SQLite 旧页。
- 自动记下后可以直接“撤销这次记忆”。
- 保存失败保留草稿并显示原因。无关更新时保留草稿，要求再确认一次。目标被忘记或切换角色时清空草稿并关闭。
- 已更正、已忘记的记录不显示原文。版本或角色变化时概览和依据一起清除。
- 主动陪伴：连续拒绝时冷却翻倍（上限 7 天），聊过一次后重置；“晚点再说”不算拒绝；专注时静默；安静时段和早安改看本地真实时钟；超过 3 天未聊有一句不施压的招呼；回忆话题不再用提问结尾。
- 默认角色增加作者人格配置 `assets/companion/xingxi_pixel_pet/persona.json`。其他角色未改。

## 顺手修掉的真实缺陷

回忆册的写操作原来把 `time.time()` 写进逻辑时钟存档，之后这条记忆的时间比较都会错。现在由宿主逻辑时钟传入。

## 真实运行发现的问题

已在本分支修复：
- 回合结束时快照用空查询再检索一次，覆盖了本轮状态，聊天证据提示在真实对话里永远不出现。现在在记忆准备完成时捕获。
- 普通闲聊被路由到 bounded 后得到 unknown，会误显示“暂时没找到依据”。现在兜底路由的 unknown 不显示。

需要 Codex 处理（真实回答原文见证据目录）：
- 已存 `我养了一只叫团子的橘猫`，问 `我的猫叫什么` 检索状态为 unknown（本地探针，未调用模型）。这是首要验收的直接失败。
- `今晚吃点什么` 走 not_needed，已知“不吃香菜”“喜欢乌龙茶”没有送达，回答没用上偏好。
- `我的吉他老师住在哪` 是 unknown 而不是 insufficient，所以角色不会说出已知的老师名字。
- 普通闲聊大量落到 bounded/unknown，模型每轮都收到 unknown 状态。
- 第二轮还出现 `我打算把全部积蓄都买彩票` 判为 sufficient，需要查是否误注入。

人格表现（我的未盲读印象，不是评审结论）：连续拒绝、低落、不同意、无据共同经历这些场景没有编造，也没有讨好。不足是未知回答过于平板，例如连续两轮“这个我不知道”，这来自 10-31 的 16 字短答规则，缺少角色味道。

## 桌面验收

用户未批准鼠标控制，所以没有做鼠标操作。证据是 `tools/memory_desktop_acceptance.py --shots=...` 在真实 Windows 窗口里由程序驱动并抓图，存于 `docs/modernization/evidence/memory-experience-20261101/screens/`。它证明页面在真实窗口平台下能渲染和走通流程，不等于人工手感验收。验收使用临时存档，没有碰真实用户存档。

## 已知未解决

- 检索泛化仍未过门槛，这是 Codex 的发布阻断。很多 `unknown` 其实是漏检，界面文案已按这一点写，但不能替代修复。
- `ask()` 走生产检索，会更新访问计数。需要 Codex 提供无副作用的只读入口。
- Host 路由未开放 change/purge，只有桌面可用。
- 外部实时状态没有真实权威接入，只显示未接入。
- 自动抽取只跑了少量种子，长期陪伴体验 not_run；真人使用 not_run。
- 桌宠模式下的证据提示和推迟按钮只有自动化测试，没有抓图。
- 主动陪伴按真实时钟的长时间体验未验证。
- `long_absence` 用墙钟，其余冷却仍是逻辑秒，应用关闭期间不走。
- 未修改 Relay、游戏 Agent、硬件固件和手机代码。
