## 2. 数据划分、评分与统计

- 按完整story/persona/archive/task语义及句式族划分60%开发、20%验证、20%密封测试；同模板替换名字、同义改写、同一故事多轮不可跨split。
- Gold包含原话、说话者、主体、字段、字面值、来源span、事件/记录/有效时间、场景、允许操作、禁止主张、无关控制事实和必要证据ID。
- 独立评测者先冻结数据hash；看过并据此改代码的holdout迁入回归，补新heldout。多轮开发诊断用过的样本不能称独立最终测试。
- 逐层查原话→持久存储→检索→实际prompt→回答/动作。回答正确不代表保存成功，保存成功不代表模型有据回答。
- 无关事实保持与可用性同时评：拒答不能掩盖漏记，全部清空不能掩盖精准遗忘失败，一律沉默不能掩盖主动性失败。
- 若N为独立同分布的合格抽样单位，0/N失败的一侧95%上界是 `1 - 0.05^(1/N)`，大N近似 `3/N`。同一story多轮、改写、seed和多个泄漏通道相关，按story聚类；设备重试不能增加独立N。人工构造压力集无总体抽样设计时只报覆盖与经验失败率。
- 人工A/B去版本、随机顺序、至少2评审+冲突裁决；事实、角色一致性、自然度、有用性独立评分，提供原句引用、一致性指标和聚类置信区间。AI judge需人工校准。
- 全部失败、超时、取消、回退保留，按模型/角色/设备/记忆规模分层，不用一个平均分掩盖关键错误。

## 4. 可执行分组方案

### M01 抽取、主体、字段与写入策略

**覆盖：**本人/亲属/同事/多个同名对象；显式事实/偏好/多事实/否定/反话/转述/假设；auto/review/off与用户明确记住；网页/屏幕/模型输出来源负例；错误分类、歧义代词、来源被截断；中文口语/错别字/英文混合/语音ASR误字。

1. 先冻结原话和gold facts/source spans/subject/slot/mode预期。
2. 确定性解析与提议校验分别运行。
3. 真实模型路径从DesktopDialogueService开始，检查最终持久存储而非仅提取JSON。
4. 每个负例保留无关控制事实，检查错误写入与漏记。
5. 修复过的案例进入回归，新增未见过测试族。

**对照：**只用本地规则；当前规则+模型提取；增强实体/来源绑定方案。

**环境：**Python/PySide6真实controller与临时存档；实际配置的模型API；记录模型精确版本和采样参数。

**频次：**PR:确定性关键族；nightly:60条轮转模型样本；release:全部1200条合同；冻结240条真实模型子集及各模式分层。

### M02 完整记忆生命周期与派生失效

**覆盖：**写入→召回→纠正→重启→遗忘→再次重启；版本链/合并/同值不同来源/歧义更正；画像/章节/向量缓存/近期对话/主动候选/TTS失效；到期/撤回/导入旧存档/备份恢复；切角色/切场景/删除部分字段保留控制事实。

1. 每story执行8–20个操作，存储和prompt分阶段断言。
2. 对遗忘前制作的所有派生内容再尝试读取。
3. 注入进程重启、事务中断、旧缓存/旧设备输入。
4. 检查原事实失效与控制事实保持。
5. 按story汇总泄漏，按表面通道另列明细。

**对照：**当前实现；候选失效/版本方案。

**环境：**真实本地存储、临时目录、真实controller；可控Clock与实际进程重启；不联网模型。

**频次：**每PR关键子集；nightly全部600故事；release全部+旧存档。

### M07 随机操作序列与状态不变量

**覆盖：**remember/correct/forget/expire/merge/restart组合；交错人物/字段/角色/场景；旧epoch与过期proposal重放；派生索引/画像/章节异步更新；随机崩溃后恢复与幂等重试。

1. 每序列使用固定seed生成20–100个合法或恶意操作，先定义reference model。
2. 每步检查当前有效事实唯一性、来源可达、角色隔离、被忘内容不进入prompt、无关事实保持。
3. 真实存储事务和进程恢复，不只测纯内存对象。
4. 失败自动缩减为最短可重现序列并保留seed/源码hash。
5. 同一seed重复与缩减序列属于相关样本，不人为增加总体N。

**对照：**reference model；当前实现；候选实现。

**环境：**真实V2/SQLite存储与临时目录；property-based工具（可用Hypothesis；引入前固定版本/许可）；无需模型网络。

**频次：**每PR:200关键seed；nightly:全部2000序列；release:固定失败回归+新增随机seed。

### M03 语义检索、无答案与预算交付

**覆盖：**词面一致/语义改写/长问题/多主体；新旧冲突/历史时点/期限/否定；多跳与需多条证据；无关问题与应保持安静；300/3000/30000条记忆规模与hard negatives。

1. 每档案按时间写入，query只读其发生前资料。

4. 先算检索，再检查预算后实际prompt。
5. 复核无答案误注入和陈旧事实名次。

**对照：**词法only；embedding only；当前RRF；RRF+阈值/时间/主体过滤；可选reranker。

**环境：**真实FastEmbed/ONNX模型与固定revision；基准CPU/GPU环境及冷/热缓存两组；不需要付费生成即可测retrieval。

### M04 章节、用户画像与共同经历

**覆盖：**单事件多派生不重复计数；真实完成/仅计划/模拟游戏/模型虚构；主题演进与互相矛盾事件；source删除/更正/到期后的整章及字段失效；超长章节/预算压缩/证据链缺失。

**对照：**当前确定性章节；带claim-source绑定的语义整理候选。

**环境：**真实V2与事件桥接；人工或双人标注；若候选LLM摘要另开真实模型组。

**频次：**PR:来源合约；weekly:80条语义审阅轮转；release:240条源链检查+抽样人工。

### M05 真实模型端到端记忆闭环

**对照：**当前主分支；候选实现；相同模型和输入。

**环境：**实际provider账号配置与额度；真实embedding缓存；桌面service/headless Qt；另有设备验收。

## 5. 发布门槛与执行节奏

### G0 版本与证据可复现

- 冻结commit/source-tree hash、依赖lock、prompt hash、model/provider、embedding revision、dataset hash、参数与时钟。
- dirty工作树必须包含patch/hash，不能只记文件名。
- 保留所有失败、取消、超时与重试，报告当前未验证部分。

### G1 核心正确性

- 支持范围内确定性合同通过；遗忘/跨角色/未经授权人格变更/重复不可逆动作零失败。
- 180旧存档语义保持与撤回不复活。
- F1人格预算、F2真实时钟、F3返回事件都有回归覆盖。

### G2 真实模型

- 冻结主模型的真实端到端与人格测试完成。
- 存储/prompt/答案分别达各指标门槛。
- 0/N泄漏只按独立story解释，不宣称绝对无泄漏。
- 副模型退化单列并可标不支持；不平均掩盖主模型失败。

### G3 真实设备

- 每宣称支持的OS/设备/App组合均有实际证据。
- 系统撤权与停止有效，无前台输入干扰或有明确接管状态。
- 测试账号下真实后置条件验证；mock、模拟器不冒充真机。

### G4 长期与成本

- 跨小时任务/重启/断网/休眠与周期性报告通过。
- 纵向陪伴无关键打扰或关系施压回归。
- tokens/延迟/资源消耗分阶段披露，并在预先约定预算内。

每PR跑对应代码的确定性合同与已知回归；nightly跑轮转真实模型和本地全量；weekly跑检索、人格代表矩阵、真实任务和性能曲线；release冻结实现后跑密封集、真机、迁移与持续任务。未执行项保持not_run，不用mock补成pass。

## 6. 预算与环境估算

所有预算均是估算方法，不填虚构执行金额。固定Python/PySide6、实际V2/SQLite、FastEmbed/ONNX和模型revision；Windows参考PC与Linux CI。移动端使用真实Android/HyperOS、iPhone/iOS及原生HarmonyOS构建环境和真机；模拟器结果单独列。长程任务需独立真实执行器、测试账号/工作区与可跨小时运行的设备。

- 调用量≈被测轮数×arm数×重复次数×（抽取概率×抽取调用数+草稿调用数+审阅概率×审阅调用数）；按实际路由拆分，本地遗忘/安静不记模型调用。
- 费用估计=各模型实际预估输入/输出tokens×执行时有效价格，加embedding/工具/基础设施；标注价格日期、币种和折扣。未核对账单不得称实际金额。
- 用预定开发批次实际usage和阶段时延校准全量上/下界，人工工时=样本数×每样本分钟×评审人数/60+冲突裁决及真机执行。
- 不做所有模型×路线×参数×设备全笛卡尔积。开发集筛选，正式集比较冻结基线+候选；主模型全量，其他family冻结代表子集，单独报告。
- 预算B分核心事实/遗忘、人格、设备、长程四块；到上限停止新增调用并保留未执行状态。性能测冷/热、p50/p95/p99、峰值内存/电量/热与主线程阻塞，失败请求不丢。

每个run保留manifest、stage trace、脱敏实际请求/回答、metrics及bad-cases。manifest记录commit/source-tree或dirty patch hash、依赖、prompt、model/provider、embedding、dataset hash和参数；不存密钥。

## 8. 外部评测复用

- [PersonaGym](https://github.com/vsamuel2003/PersonaGym)：人格维度和评分管线；根代码MIT，保留来源；中文多轮与生命周期另补。
- [PersonaMem-v2](https://huggingface.co/datasets/bowen-upenn/PersonaMem-v2/raw/main/README.md)：动态隐含偏好和无关个性化；官方数据卡CC BY 4.0；代码和数据分别核验。
- [PersonaMem-v3](https://huggingface.co/datasets/bowen-upenn/PersonaMem-v3/raw/main/README.md)：跨平台、主动性、过度个性化与因果评测设计；官方数据卡CC BY-NC 4.0；不按MIT作为产品数据打包。

外部benchmark用于参照与复用评分工具，不替代中文桌宠、多端撤回、真机和长期体验，也不要求更换现有记忆存储。


## 6. 本轮之后的实验顺序

1. 先完成B1所有入口的相同处理语义与B2实体/字段/时间语义；使用本轮已失败的实际案例作为回归。
2. 冻结新的开发/验证/密封检索数据，覆盖不需要个人化、无相关证据、同名主体、旧值、计划/完成及跨场景难负例。50条开发诊断不能继续充当密封集。
3. 检索消融按只加相关性门控、独立词法/向量列表RRF、实体时间过滤、候选去重、多样性、必要时reranker逐项比较；相同语料和预算，先提高无答案准确性。
4. 存储性能先比较一致快照与同SQLite规范化表，再决定词项索引、增量向量缓存或ANN；记录迁移和撤销一致性。
5. 锁定一个候选后跑完整真实生成闭环。分别评分有据事实、恰当未知、自然表达和人格；不能以检索Recall替代回答正确性。
6. TASK-03单独扩充环境经验测试：应用/版本/前提、成功失败、工作流和反例。参考LongMemEval-V2，不与用户事实混为一项准确率。
