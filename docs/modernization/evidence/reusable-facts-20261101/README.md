# 人物关系与事实更正的复用验证

本目录所有人物、姓名、地点、职业和活动均为合成测试数据。它们不代表用户资料，不进入默认角色记忆，不构成新的产品需求。测试工具只在显式运行时创建独立存档。

## 发现与改动

基线为 `c32c657`。审查发现生产代码没有写死示例姓名或游泳日期，但有 `teacher_name` 专用解析；每周活动解析要求包含“去”，不能处理练习、参加等其他直接表达。语义抽取还把部分明确关系自述整体排除。字段遗忘缺乏人物主体约束，会把关系人物的居住地请求匹配到用户本人的居住地。

本次使用共享的原话事实绑定：关系标签、字段、字面值。人物姓名、居住地和职业按主体与字段隔离；每周安排按原话活动隔离。关系与活动不来自案例名单，模型也不能用分类或目标 ID 改变原话主体。继续复用现有来源、V2 存储、纠正、待确认、epoch 和失效传播。

旧明确记忆与旧教师字段只在读取时参与统一匹配，不扫描历史重新提取、不改变存档格式。代词不明、多目标、转述和假设不自动补事实；没有既有每周安排时，不能从一个星期几推断重复频率。这仍是有边界的事实处理能力，不是任意自然语言关系或日程理解。

职业样本暴露了“是”系词的第二个缺口。当前实现仅在语义抽取明确分类为职业时提供字段提示，绑定完整原话及旧授权事实；普通“是……”描述不会由本地规则默认当成职业。新摘要规范为人物职业事实，以后按原路径召回、遗忘。职业词义仍由模型分类，宿主验证字面来源、主体及目标，不宣称独立判定职业语义。

## 评测方法

`cases.json` 由独立工作单元在读取新生产实现前编写，冻结输入与检查条件；生产实现者不接收案例具体值。使用应用真实 `deepseek-flash`（用户指定 V4.1 Flash），通过实际桌面 controller、记忆服务和对话服务运行。

每个案例在独立存档中执行：初始保存 → 更正 → 清空聊天历史、关闭并重新创建 controller → 召回 → 遗忘 → 即时询问 → 再次清空历史并重启询问。记录 active facts、metadata、epoch、历史上下文以及实际模型请求/回答、usage、延迟。只在存储和实际 prompt 同时满足条件时才判定记忆成功。

修复前代码从单独的 `reusable-facts-baseline` 工作目录加载；评测脚本的 `--repo` 同时控制生产模块与辅助工具导入，防止新代码混入基线。原始回答及服务失败保留，不覆盖失败证据。

运行方式（在仓库根目录）：

```powershell
$env:PYTHONUTF8='1'
$env:QT_QPA_PLATFORM='offscreen'
python tools/reusable_facts_flash_eval.py --dataset docs/modernization/evidence/reusable-facts-20261101/cases.json --output artifacts/codex_handoff/reusable-facts-run.json
```

应用需要已有有效模型配置与本地语义模型缓存。报告不包含凭据。测试使用合成输入与真实模型；有限样本结果不能代替人工长期角色体验。

## 真实结果与问题记录

- 修复前六例：`before.json`；另一个职业样本：`before-occupation.json`。六例更正均未保存；字段遗忘误删本人住址。职业基线把亲人职业误存为本人职业，回复却声称区分了人物。读书会一轮空输出触发回退，实际请求及前次输出仍有旧日期。
- 第一版七例：`after.json`。室友、邻居、表姐居住地、书法、读书会、同事/邻居/本人隔离六条链路通过；职业例避免了错写本人，但更正及遗忘均拒绝执行，旧职业继续进入请求。
- 职业补修：`occupation-final.json`。同一冻结样本保存新职业，清空历史重启答新职业；只遗忘职业后保留人物姓名及本人职业，两次后续询问无旧新职业。原失败文件保留。
- 旧链回归：`teacher-regression.json`、`schedule-regression.json`，验证原教师姓名和游泳改期的保存、空历史重启召回与遗忘。
- 风格问题仍保留：教师更正回复有“这名字听着就像会弹吉他的人”的无依据姓名联想；书法初次分享后有额外追问。不能把记忆通过写成人格全面达标。

独立审阅见 `before-review.md`、`after-review.md` 及最终复核记录。模型请求、原始输出、实际 tokens 与逐次延迟均在 JSON 中；本地合约测试不是这些模型结果的替代。

最终证据组合为 `after.json` 前六例加 `occupation-final.json`，不是挑掉第七例后宣称原文件全过：

| 指标 | 结果 |
| --- | --- |
| 更正持久保存 | 7/7 |
| 空聊天历史重启后，实际 prompt 交付新值、排除旧值 | 7/7 |
| 重启回答正确 | 7/7 |
| 遗忘后即时及重启请求、回答不泄露目标新旧值 | 14/14 |
| 有控制事实的样本保留无关事实 | 5/5 |

七例最终组合共 61 次实际调用、160,297 tokens、115,280 ms 调用延迟之和；加两条旧链回归为 77 次、201,323 tokens。包含全部基线及中间失败为 156 次、406,099 tokens。调用延迟之和不等于端到端用时，实际计费金额未核实。逐项复核和统计口径见 [最终独立复核](final-review.md)。这里检查的是持久事实及 prompt 交付，不能另行宣称 embedding 检索排名质量已完成独立评测。

## 时序

`after.json` 启动后追加了反话与转述拒绝规则；职业补修之后还有模型错误分类不得写入本人属性的保护。它们由相应负例合约覆盖，不将此前正向模型运行当作这些负例的真实模型验收。两次进行中的全量运行因补充上述实际缺陷修复而中断，日志分别为 `full-pytest-interrupted.log`、`full-pytest-interrupted-2.log`；均不计作完整回归通过。最终完整回归另行保存。
