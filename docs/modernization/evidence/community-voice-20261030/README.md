# 社区方案对照与有限表达修订 — 2026-10-30

基线 `0fef27f`，工作分支 `codex/desktop-acceptance`。用户要求继续修复 8 项部分通过的表达问题，并查阅开发者社区做真实对照。本批仍用应用配置的 `deepseek-flash`（V4.1 Flash）；没有更换模型、修改角色包或推送。

## 查阅资料与实际取舍

- [SillyTavern 官方 Prompts 文档](https://docs.sillytavern.app/usage/prompts/)建议检查实际拼装的提示、优先表达希望模型做什么，并使用例句和适当的指令位置。查阅了其 [Author's Note 文档](https://docs.sillytavern.app/usage/core-concepts/authors-note/)说明的历史后指令位置。
- [开发者社区关于正向规则与例句的讨论](https://www.reddit.com/r/SillyTavernAI/comments/1pftmb3/yet_another_prompting_tutorial_that_nobody_asked/)既有人报告例句有效，也有人报告例句内容被反复套用、虚构感官场景扩散。这些是个人经验，不能直接推定对 Flash 有效。
- [Self-Refine 研究](https://selfrefine.info/)及其[实际对话修订实现](https://github.com/madaan/self-refine/blob/main/src/responsegen/task_iterate.py)采用有针对性的反馈后修订。本批仅借鉴反馈应具体到问题的思路，自行编写规则、复用现有网络客户端；没有复制第三方提示词或代码，也没有实现无上限迭代。
- [RoleFact 论文](https://arxiv.org/abs/2406.17260)研究了角色知识范围外的幻觉，但其校准方法和数据条件不同，本批没有直接移植或声称复现论文指标。

## 最终实现边界

真实聊天先生成草稿，再由同一个模型依据当前消息、有效记忆、近期对话、稳定角色和临时上下文修订一次。修订明确区分用户改口与角色先前答错；反馈必须指出有问题的草稿短语，最终仍使用角色口语。该方法仍依赖模型判断，`edits` 本身不是独立事实证明。

- 只对非空聊天、支持 JSON 的现有 chat-completion 客户端启用；动作、空消息、事实抽取不增加修订调用。
- 两次调用共用一个 future、总 deadline 与取消事件；第二次 HTTP 请求仅使用剩余时间，并在发起前检查取消。已在途的请求仍可能返回，桌面和宿主继续通过原有线程与最终角色/epoch 校验阻止迟到结果提交。
- 草稿不发布到聊天、历史、TTS 或缓存；只提交最终通过原事件校验的台词。修订不能修改演出字段或持久状态。
- 草稿偶尔返回普通文字时，在同一次修订中处理格式；最多两次调用，没有第三次盲目重试。修订本身失败则明确走失败路径，不偷偷显示未修订草稿。
- 审阅证据独立序列化；临时屏幕、工具和插件内容不作为长期事实或角色亲历。完整证据超过现有 8192 字符限制时明确报错，不裁剪后假称已审阅完整上下文。

成本有所增加：相同 16 场景，基线 34 次调用 / 71,946 token，最终 58 次调用 / 122,318 token，实际 token 增加约 70%。新增控制样本另用 2 次调用 / 4,545 token。原 8 项完整场景耗时中位数从 3,991.5 ms 变为 11,321 ms；独立 8 项从 3,518.5 ms 变为 14,448 ms。这里包含多轮、抽取、存储和重开操作，不是单条聊天延迟，也不是服务延迟的统计估计。最后 17 项单次调用中位耗时为 2,379.5 ms；逐次记录见 JSON。

实际例子：反对通宵证明努力时，最终说“我不太会把通宵当成‘够努力’的证明”；改地点时直接接“泉州”，不再补“我记岔了”；云的发挥明确说成“我脑子里已经能想象”，保留拟人玩笑。中间 `structured-final` 的云场景实际出现裸文本草稿，被同一修订调用恢复成有效协议，最终没有格式 fallback；不是靠放宽本地解析接受裸文本。

## 已确认的问题与验收限制

新样本 `community_corrected_teacher` 暴露了**既有第三人信息持久纠正缺口**，基线和最终都存在。中间轮模型找到旧目标并标 personal，但“写错”未被识别为明确纠正，控制器返回澄清；最终轮模型标为 other，被当前仅自动抽取用户本人事实的边界忽略。后续回答从近期聊天取得新名字江屿，而长期事实仍含老师叫林澈、epoch 未推进。因此 `missing/leaked` 仍失败，不能因最终文字答对而认定纠正成功。只加“写错”关键词也不够：姓名模板会错误转成用户自己的姓名；后续支持需保留已有关系主语并明确第三人事实边界。本批未修改记忆领域或隐藏此问题。

有来源的过敏控制样本已实际持久保存、重开、把芒果交付 prompt，并回答芒果；原空 seed 样本仅评当前原则。这批没有新增真实模型遗忘场景，38 条开发契约的遗忘检查不冒充模型泄漏率。

最终完整回归 **1676 passed / 5 skipped / 3 warnings**（293.69 秒），见 `full-pytest-accepted.log`；38 条开发记忆契约全过。跳过项仍为显式 provider 测试及平台符号链接限制，真实 Flash 调用另行完成；警告仍为既有 websockets 弃用与端口占用测试中的 uvicorn 线程异常。契约测试验证实际 HTTP、取消、剩余预算、空消息不修订、完整证据与协议形状；回放模型文本的测试不作为质量证据。没有新增依赖、存档迁移或 UI 改动。
