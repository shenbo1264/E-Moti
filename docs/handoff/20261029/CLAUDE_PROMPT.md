# 给 Claude：E-Moti 产品与前端开发

你负责 E-Moti 的产品设计和前端实际开发，Codex负责后端与宿主服务。请读取工作区真实代码和本交接包，直接推进职责内实现、测试与修正，不只输出PRD或等待用户逐项确认。

## 产品目标与最新更正

E-Moti是可独立存在、拥有稳定人格和共同记忆的个人AI伙伴。工作、游戏和设备观察都是可选能力；关闭工作插件后仍能聊天、娱乐和休息。希望角色好奇、聪明、自然、有自己的表达风格和判断，偶尔轻度吐槽，不过度讨好或打扰。情绪影响表达，不改写事实。

范围：保留Windows优先的Python/PySide6桌面，新增Android/HyperOS手机、iPhone/iOS、华为手机原生HarmonyOS。用户之前说macOS是口误，不开发Mac桌面；鸿蒙只指华为手机，不能以PC/二合一或OpenHarmony系统权限推断手机App能力。iOS构建使用Mac/Xcode是开发条件。

手机应能与同一角色聊天、管理记忆、主动分享；连接电脑后，用户可以指挥Relay及生态软件执行任务、查看阶段报告和取消状态。可选观察手机活动/屏幕以理解用户，但不同平台权限和覆盖独立展示；无需观察授权也能聊天和远程工作。

## 按用户闭环推进

先完成：真实Android客户端配对宿主→同角色聊天→明确记住并确认→另一端纠正/遗忘→旧事实及派生信息失效→角色人格保持稳定。该切片不依赖Relay。

随后接真实任务：建议/指令→用户采纳→执行者接受→带时间、来源、成果证据的阶段报告→取消或完成。准确区分待发送、投递未知、已接受、运行、过时、取消请求、取消确认和执行者报告完成。工作报告不占据全部陪伴体验，复用安静模式和低频交互。

必要页面包括：聊天/角色、记忆与来源、任务建议和进度、设备配对与连接状态、观察范围与授权。先覆盖完整闭环所需状态，再改善视觉细节；不以大量静态页面代替真实连接。前端fixture可以用于布局，但要明示，不能算端到端验收。

观察先做主动分享，再接系统允许的应用/媒体/屏幕来源。总开关需对应各项OS授权；保留来源/时间/有效期，区分用户与他人的文字。新观察派生聊天、摘要、TTS和缓存的撤回链完成前，不启用被动采集。iOS与华为手机严格按新平台研究，不承诺所有App都可读。

记忆质量作为并行产品线：完善可检查/确认/纠正/遗忘体验；给出跨休闲/游戏/工作/拒绝场景的人格rubric，与Codex的真实模型评测结合。自动人格成长和普通聊天全量抽取目前未实现，不标成现成功能。
