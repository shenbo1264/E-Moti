# E-Moti 完整需求汇总

日期：2026-10-29（America/Los_Angeles）。本文件汇总本轮及此前本项目对话中的明确需求；它描述产品目标，不把目标写成已完成能力。当前实现见 [current-state.md](current-state.md)，分工见 [work-allocation.md](work-allocation.md)。

## 1. 定位与范围

E-Moti 是可以独立存在、具有稳定人格和共同记忆的个人 AI 伙伴。桌宠是已有交互形式，手机是新增入口；工作、游戏、现实感知通过可选能力扩展。用户可以关闭全部工作插件，仅聊天、娱乐、休息。

角色体验：好奇、聪明、自然，有自己的表达习惯和判断，偶尔可以轻度吐槽；避免过度讨好、频繁打扰和将休闲行为解释成需要纠正的效率问题。情绪影响表达，不改写事实；安静、离线或拒绝建议不应成为惩罚关系的理由。

项目关系：

| 项目 | 本项目应承担的连接 | 保留在外部项目的职责 |
|---|---|---|
| Relay | 传递用户授权的请求、读取任务进度、阶段汇报和结果引用 | 多 Agent 调度、Codex/Claude 等执行者管理、真实任务/权限/验收状态 |
| Game Companion Agent | 读取游戏状态、共享当前角色的表达与经确认的共同经历 | 游戏执行逻辑、世界状态、行为树和游戏适配 |
| E-Moti Body | 预留统一角色与交互协议 | ESP32-S3 固件、硬件接线与设备驱动 |

本次开发只修改 E-Moti。外部接口缺失时列出需要对方提供的最小能力，不能擅自在其他仓库重构。用户已授权继续开发 E-Moti；真实设备授权、账号操作、发布和外部系统改动按实际授权执行。

## 2. 平台范围更正

- 现有桌面：Windows 优先，Python 3.11+ / PySide6；保留桌宠、托盘、控制面板和现有渲染器。
- 首要手机：Android，用户目前自述 HyperOS 4；具体机型、地区包、build/API 级别仍待真机确认。
- 后续手机：Apple iPhone 的 **iOS**；此前“macOS”是用户口误，不安排 Mac 桌面客户端开发。
- 后续手机：**华为手机原生 HarmonyOS**；不能拿鸿蒙 PC、2-in-1、OpenHarmony 系统签名或旧 Android 兼容环境的能力直接承诺手机三方 App 可用。
- iOS 的 macOS/Xcode 构建环境属于开发条件，与 Mac 桌面产品需求分开。

三端共用人格、记忆、任务语义与服务契约；系统观察能力按平台实际权限分别实现。详细更正在 [platform-scope.md](platform-scope.md)。

## 3. 人格、用户事实与共同经历

### 稳定人格

由 Character Pack 及可选人格配置提供角色身份、表达风格、偏好、行为倾向、互动习惯和边界。不能被一次聊天、用户事实纠正或屏幕文本重写。允许共同经历带来有限、可解释、可查看的变化；自动人格演进是待开发目标，不能冒称当前已实现。

### 用户事实与偏好

记住用户明确表达或确认的信息，保存来源、发生/记录时间、置信度、版本、有效期、owner、角色与场景。用户可以检查、增加、确认、纠正、遗忘；需要说明“以后不再用于推理”和“清除磁盘/历史副本”的不同范围。无依据的信息保持候选或未知。

### 共同经历与情节记忆

记录双方实际参与或外部权威系统确认完成的事件，例如第一次共同完成任务、游戏里程碑和重要互动。阶段回忆、关系章节、画像必须指向有效来源；模型生成的故事、假设、角色扮演、计划和执行者尚未完成的任务不能直接成为共同经历。

### 必须保住的生命周期

**记住 → 正确召回并进入实际 prompt → 用户纠正 → 旧事实失效 → 遗忘 → 章节/画像/旧聊天/缓存/在途结果同步失效 → 人格稳定。**

这条要求涵盖 Emotional Memory V2、CoreBondProfile、章节、旧存档迁移、AI Context Builder、typed request、最终模型输入，以及未来新增的手机派生信息。只在检索列表中删除一行不足以完成遗忘。

### 工作、游戏与观察

工作进度、游戏世界状态、页面内容是有来源与有效期的短期上下文。外部系统拥有权威状态。长期写入必须有独立、明确的依据，不能因反复出现在模型上下文中而自动变成人格偏好。

## 4. 主动、长程、可靠

| 维度 | 用户要求 | 可验收行为 |
|---|---|---|
| 主动 | 适时提出有帮助的建议，采纳后继续执行 | 建议可忽略/拒绝；有安静模式、冷却、拒绝后退让；授权绑定具体目标与范围 |
| 长程 | 长时间推进目标、跟进生态内执行者并阶段报告 | 任务脱离单轮聊天持久存在；宿主重启/断线后可恢复；有预算、期限、检查节奏和阻塞处理 |
| 可靠 | 工作时状态和结果可信 | 接受、运行、完成、验收分开；失败/过时/未知可见；报告带来源与证据；取消有回执；重试不盲目重复副作用 |

授权范围内的查询、进度跟踪与普通继续推进不反复询问。目标、权限或预算发生实质扩大时再处理新的授权。不能从网页、观察文本、模型输出的 `approved=true` 推断用户已同意。

阶段汇报应回答：谁报告、何时核对、完成了什么、产物/测试在哪里、当前阻塞、下一步。角色可以自然表达，但不能修改事实卡片。手机推送是提醒，任务日志和外部权威记录才是状态来源。

连续工作由电脑或用户选择的常开宿主负责。手机后台保活不承担任务正确性；电脑睡眠、关机、断网时准确显示状态，不能虚构进展。跨主机搬迁需有明确记忆权威，不先引入多主同步系统。

## 5. 手机交互与观察

### 基本闭环

手机聊天/语音 → 同一 E-Moti 角色与记忆 → 用户下达或采纳任务 → 向电脑 Relay/其他能力发送已授权请求 → 读取真实进度 → 手机上的阶段报告、暂停/取消和结果查看。

聊天、工作、观察可以独立开关；关闭观察不影响聊天或远程任务。手机具备查看/纠正/遗忘记忆的入口，不能只能新增而不能管理。

### 观察目标

了解用户近期在手机做什么，例如前台应用、主动分享的网页、允许的媒体信息、通知片段、用户启动的屏幕会话和平台允许的可访问文本。研究浏览器、哔哩哔哩、微信等真实应用的覆盖，而不是依据 API 名字承诺全量可见。

用于学习需求、偏好、表达习惯时区分用户本人、对方、网页引用、游戏角色与虚构内容。优先提取可检查的偏好候选；不默认全天收集后自动训练模型或把全部文字归为用户语料。

### 用户控制

提供总开关和按来源/App 的范围设置。系统授权按操作系统分别请求；展示正在采集、暂停、权限不足、系统限制、无可见内容和离线等真实状态。支持保留时间、查看来源、撤回、删除范围和采集空窗说明。

撤回要传播到采集器、上传队列、OCR/VLM 待处理结果、宿主上下文、派生聊天/摘要、TTS 与设备缓存。重连先应用失效记录，再恢复旧缓存。已发给外部模型的数据不能通过本地开关追溯撤回，界面按实际范围说明。

### root 与平台适配

普通手机聊天、远程请求和主动分享以无需 root/越狱为默认。Android 观察逐项评估 Usage Access、通知访问、Accessibility、MediaProjection；ADB/scrcpy/Shizuku 作为可选高级或调试路径。确实需要 root/系统签名/特殊 entitlement 的能力单列，不能包装成默认功能。iOS 与华为手机鸿蒙不沿用 Android 权限表。

## 6. 工程与复用要求

- 增量升级现有 Python/PySide6 架构，保留 Emotional Memory V2、CoreBondProfile、Character Pack、Plugin Runtime、LLM/ASR/TTS/视觉入口；重构需说明具体收益。
- 保留用户存档、角色、资源和迁移源；先在副本验收迁移。损坏与未知 schema 明确报错，不静默回退旧数据导致被遗忘信息复活。
- 继续使用一个权威长期记忆存储；任务日志有独立职责，不能再积累第二份用户画像。语义索引若新增，应能从有效记忆重建并响应撤回。
- 优先研究并复用合法、成熟、适配的代码；记录实际提交、许可证、文件、修改与维护成本。不是只列项目名字，也不为避免依赖重复开发成熟基础设施。
- 现有 Graphiti RRF 复用与许可证保留；Letta/Mem0/Graphiti、AIRI/Open-LLM-VTuber/OpenClaw 等研究在 `docs/modernization/`。手机项目的固定来源在 `docs/modernization/mobile/`。
- 发现问题已经由最新补丁/PR/开发包解决时，复用或合并，避免重复重写。
- 文件所有权、线程边界、类型化契约保持清楚；不要让网络回调直接并发写 Qt 对象或同一角色存档。
- 仅增加当前需求或真实故障需要的复杂度。成熟网络/认证库可采用，不要求手写 TLS、密码协议、通用工作流平台或全新记忆框架。
- 检查最新分支和进行中的 PR，不覆盖别人的改动。不擅自推送、发布、改仓库可见性或删除真实用户数据。

## 7. 评测要求

| 指标 | 必须说明的口径 |
|---|---|
| 正确召回 | 检索命中、进入最终 prompt、模型回答正确分别报告 |
| 无关误召回 | 负例中引入无关事实的比例与具体例子 |
| 过时事实引用 | 纠正、过期后旧值是否进入上下文/回答 |
| 遗忘泄露 | 来源、画像、章节、聊天、缓存、迁移与迟到结果分别覆盖 |
| 跨角色/用户/场景污染 | 检查身份、角色和 scope，不只检查相似度 |
| 虚构共同经历 | 区分禁止写入的事件与模型自行叙述的幻觉 |
| 人格一致性 | 跨聊天/游戏/工作/拒绝/情绪场景评价风格；配置 hash 只测配置 |
| Token 与延迟 | 实际 provider usage、首 token、完整响应、本地构造分别记录 |

保留 38 条确定性开发用例和 before/after；另建未用于调试的 holdout，再做真实模型对照。任务/设备增加：重复执行、未知结果恢复、取消确认、进度新鲜度、权限撤回后泄露、耗电与漏采。结果有分母和真实 bad case；未运行的项目写 `not_run`。
