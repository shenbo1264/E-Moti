# 开发切片与验收

这是后续开发的验收目标，不是本次交接已经跑通的结果。已执行证据见 [current-state.md](current-state.md)。

## A. 跨端伙伴与记忆闭环

第一条切片不依赖Relay：Android手机配对到实际E-Moti宿主，使用桌面当前角色聊天，能在一端记住事实、另一端查看/纠正/遗忘，最终模型输入排除旧事实，当前角色配置不被事实操作改变。

必要场景：

1. 无工作插件、无观察授权时仍可聊天；无LLM凭据时如实使用现有本地表达，不能冒充实模型对话。
2. 设备凭据正确绑定owner/角色权限；篡改请求正文不会读写其他角色或用户存储。
3. 记忆显式确认、来源查看、修改、遗忘与相关旧聊天/章节/画像失效沿用现有服务；手机没有第二套记忆库。
4. 桌面切角、手机重连、两端同时发送消息时状态串行一致；旧版本回复不被展示或朗读。
5. 电脑离线、配对被撤销和请求失败有真实状态，恢复后按服务端版本补齐。

Claude交付实际页面与客户端，Codex交付可运行宿主/契约；记录手机型号/build、服务commit、请求/响应与实际操作。fixture仅验布局或单元规则。

## B. 授权任务与长程监督

在实际Relay可用接口上运行一项有明确范围的小任务：提出/输入目标→用户采纳→派发前日志→真实执行者接受→阶段进度→产物/测试来源→取消或完成。

核查重复提交、发送后丢回执、客户端断线、宿主重启、外部事件乱序、状态过期、取消与完成竞态。未知状态先核对；未完成独立验收时只能标为执行者报告完成。缺失下游command-ID查询/取消时显示实际能力，不补造成功结果。

增加runner后再做真实跨小时任务，记录检查节奏、预算/期限、阻塞与恢复、汇报频率。不要将本地18项smoke重新命名为这条真实链路验收。

## C. 可选手机观察

先用户主动分享，再逐项增加平台允许的数据来源。每类观察记录来源、采集时间、授权会话、有效期和说话者归属。把网页或他人的文本当成用户命令/用户偏好属于失败。

手机总开关关闭、OS撤权、会话停止、切角、过期和重新连接时，验证采集停止、迟到结果拒绝、派生聊天/章节/摘要过滤、TTS停止与客户端缓存撤回。仅调用buffer.clear/revoke不算完成全链路。

屏幕保护、无可访问节点、后台中断属于有效产品状态；不应伪造画面或将“读不到”解释为“用户无活动”。分别记录覆盖率、采集空窗、端到端延迟和额外耗电。

## D. 回归与持续质量

保留38条开发memory契约及现有角色/插件/UI回归。冻结新增holdout后再做真实模型A/B：无记忆、当前有效记忆、可选语义增强使用相同人格和预算。输出正确召回、无关记忆、过时引用、遗忘泄露、跨角色/场景、虚构共同经历、人格行为、provider token usage与延迟；保留原始bad case和分母。

对生产改动先相关测试再按根AGENTS要求做全量回归；文档-only变化只做链接/格式等轻量检查。UI/资产改动实际观察页面；打包改动再运行对应Windows构建/安装器验证。没有工具/设备/账号时明确未验，并继续完成不依赖它们的工作。

验收记录只需包含：被测版本、环境、实际命令或操作、预期与结果、证据位置、失败/未运行项。复用有效记录，不为每个小改动新增空洞审计层。
