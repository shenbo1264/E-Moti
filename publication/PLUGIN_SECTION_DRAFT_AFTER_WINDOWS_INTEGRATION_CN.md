## 我给 E-Moti 留了一扇门

做完热牛奶记忆和回忆册之后，我开始考虑另一个问题：以后再加一个小游戏、一套语音服务，或者一种新的角色互动，是否每次都要改 `controller.py` 和主界面？

最近开源的 DeepSeek Harness 给了我一个很直接的启发。它把模型、工具、会话和界面都放进插件体系，功能通过明确接口注册，卸载时再把自己的影响完整收回。

E-Moti 的技术栈和它不同。我保留了 Python、PySide6、本地状态机和现有角色包，在外面加了一层独立的 Plugin Runtime。插件可以增加玩家动作、角色 Skill、记忆规则、表达上下文和小型界面；LLM、TTS、ASR、屏幕摘要与搜索也有了统一的能力接口。

我先做了一个很小的例子，叫“星图角落”。启用后，互动区会出现“一起看星星”。第一次完成这项互动，回忆册会留下《第一次一起看星星》；第二次只更新累计次数；关闭插件后，动作和面板会从界面里消失，原来的养成系统继续运行。

插件读取的是游戏状态快照。金币、背包、关系和存档仍由本地规则结算。联网、屏幕摘要和凭据属于单独权限，本地安装的插件也需要玩家亲自启用。

当前版本面向内置插件和可信源码。同进程 Python 插件仍有明确的安全边界。第三方分发会放在后续阶段，届时再补子进程隔离、签名和来源验证。
